# localhost

> 지금 쓰고 있는 내 컴퓨터 자신을 가리키는 이름이다. 브라우저에 `localhost`를 치면 내 컴퓨터 안의 서버 프로그램에 접속한다.

## 설명
- 모든 컴퓨터는 자기 자신을 부르는 특별한 이름을 하나 가진다. 그 이름이 `localhost`다.
- `localhost`는 [[IP 주소]] `127.0.0.1`과 같은 곳을 가리킨다. IPv6에서는 `::1`이다. 이 주소를 루프백(loopback, 되돌아오는 고리) 주소라고 부른다.
- `localhost`로 보낸 데이터는 컴퓨터 밖으로 나가지 않는다. 데이터가 [[인터넷]]을 거치지 않고 같은 컴퓨터 안에서 바로 되돌아온다.
- 보통 `localhost:3000`처럼 뒤에 [[포트]] 번호를 붙인다. `localhost`는 "어느 컴퓨터인지"를 알려주고, 포트 번호는 "그 컴퓨터의 어느 프로그램인지"를 알려준다.

| 주소 | 뜻 |
|---|---|
| `localhost` | 내 컴퓨터 |
| `127.0.0.1` | 내 컴퓨터 (숫자로 쓴 이름) |
| `localhost:3000` | 내 컴퓨터에서 3000번 포트를 쓰는 프로그램 |
| `localhost:5173` | 내 컴퓨터에서 5173번 포트를 쓰는 프로그램 (Vite 기본값) |

## 비유
집 안의 인터폰이다. 인터폰으로 다른 방을 부르면 바깥 도로로 나가지 않고 집 안에서만 연결된다. 방 번호가 [[포트]] 번호와 같다. 이웃은 우리 집 인터폰으로 우리 방을 부를 수 없다.

## 헷갈리기 쉬운 점
- localhost ≠ 인터넷 사이트. `localhost` 주소를 친구에게 보내면 친구의 브라우저는 친구 자신의 컴퓨터를 찾는다. 친구는 내 화면을 볼 수 없다. 남에게 보여주려면 배포해야 한다 → [[웹 호스팅]]
- 모든 컴퓨터가 각자 자기만의 `localhost`를 가진다. 이름은 같지만 컴퓨터마다 가리키는 대상이 다르다.
- [[서버]] 프로그램이 꺼져 있으면 `localhost`에 접속할 수 없다. 터미널에서 `npm run dev`를 끄면 브라우저는 "사이트에 연결할 수 없음" 같은 에러를 보여준다.
- 같은 와이파이에 있는 내 폰에서도 `localhost`로는 노트북에 접속할 수 없다. 폰에서 `localhost`는 폰 자신을 가리키기 때문이다. 이때는 노트북의 내부 IP 주소(예: `192.168.0.10`)를 써야 하고, 개발 서버에서 따로 설정을 켜야 할 때가 많다.

## 웹 개발에서는
- `npm run dev`를 실행하면 내 컴퓨터에 개발 서버가 켜진다. 터미널에 `http://localhost:3000` 같은 주소가 나온다. 이 주소를 [[브라우저]]로 열면 만들고 있는 사이트를 바로 볼 수 있다.
- 이때 한 컴퓨터가 [[서버]]와 [[클라이언트]]의 역할을 둘 다 한다.
- 프론트엔드와 백엔드를 같이 켜면 포트 번호가 서로 다르다. 예를 들어 화면은 `localhost:3000`, API 서버는 `localhost:8000`을 쓴다. 포트가 다르면 브라우저는 서로 다른 출처로 보기 때문에 CORS 에러가 날 수 있다.
- 개발할 때는 API 주소가 `localhost`이고, 배포하면 실제 [[도메인]]으로 바뀐다. 그래서 주소를 코드에 직접 쓰지 않고 [[환경 변수]]에 넣어 둔다.
- AI에게 "localhost에서는 되는데 배포하면 안 된다"고 물으면 환경 변수나 주소 설정 문제인 경우가 많다.
