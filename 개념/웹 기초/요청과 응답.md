# 요청과 응답

> 클라이언트가 "이거 줘" 하고 보내는 메시지가 요청, 서버가 "여기 있어" 하고 돌려주는 메시지가 응답이다. 웹의 모든 통신은 이 한 쌍으로 이루어진다.

## 설명
```
클라이언트 ──요청──▶ 서버
클라이언트 ◀──응답── 서버
```

| | 요청 (Request) | 응답 (Response) |
|---|---|---|
| 보내는 쪽 | [[클라이언트]] | [[서버]] |
| 들어 있는 것 | 어디로([[URL]]), 무엇을 할지([[HTTP 메소드]]), 추가 정보(헤더), 보낼 내용(본문) | 결과 번호([[HTTP 상태 코드]]), 추가 정보(헤더), 받을 내용(본문) |
| 예 | "GET /images/cat.jpg 주세요" | "200 성공, 여기 사진 데이터" |

- 항상 클라이언트가 먼저 요청하고, 서버는 요청을 받아야 응답한다.
- 요청 하나에 응답은 하나다. 웹 페이지 하나를 열 때 요청이 수십 번 오가는 건, 이미지·CSS·JS를 각각 따로 요청하기 때문이다.
- 이 대화 규칙이 [[HTTP]]다.

## 비유
식당 주문. 손님이 "김치찌개 하나요"(요청)라고 하면 주방이 김치찌개(응답)를 내보낸다. 메뉴에 없으면 "그건 없어요"(404)라고 답한다.

## 헷갈리기 쉬운 점
- 다운로드도 요청과 응답이다. "이 파일 줘"라는 요청에 서버가 파일 데이터로 응답하는 것이다.
- 업로드도 요청과 응답이다. "이 파일 받아줘"라는 요청에 파일을 실어 보내고, 서버가 "잘 받았어"로 응답한다.

## 웹 개발에서는
- 개발자 도구(F12) → Network 탭에서 요청 하나를 누르면 요청과 응답 내용을 그대로 볼 수 있다.
- 바이브코딩 중 "API를 호출한다", "fetch한다"는 말은 서버에 요청을 보낸다는 뜻이다 → [[API]]
