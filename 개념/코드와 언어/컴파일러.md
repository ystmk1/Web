# 컴파일러

> 사람이 쓴 코드를 실행하기 전에 통째로 기계어로 번역해두는 프로그램. 실행하면서 번역하는 쪽은 인터프리터라고 한다.

## 설명
| | 컴파일 | 인터프리트 |
|---|---|---|
| 번역 시점 | 실행 전에 통째로 | 실행하면서 |
| 비유 | 책을 미리 번역해서 출판 | 동시통역 |
| 결과물 | 실행 파일 (.exe 등) | 따로 없음 |
| 대표 언어 | C, C++, Rust, Go, Swift | Python, JavaScript (전통적인 구분) |

- 요즘은 둘을 섞어 쓴다. 크롬은 [[JavaScript]]를 실행하다가 자주 쓰는 부분을 그 자리에서 기계어로 번역해둔다(JIT 컴파일). 그래서 "컴파일 언어 / 인터프리터 언어"는 대략적인 구분이다.
- Java·C#·Kotlin은 중간 코드(바이트코드)로 먼저 번역하고, 실행할 때 가상 머신이 다시 기계어로 바꾼다. [[Python]]도 안에서는 바이트코드로 바꾼 뒤 실행한다.

### 트랜스파일
기계어까지 가지 않고, 한 프로그래밍 언어를 다른 프로그래밍 언어로 바꾸는 번역이다. 브라우저는 JavaScript만 실행하기 때문에, TypeScript나 [[React]]의 JSX는 JavaScript로 바꿔야 한다.

```
TypeScript (.ts)  → JavaScript (.js)
JSX (React 코드)  → JavaScript
```

## 비유
번역가. 컴파일러는 책 한 권을 미리 번역해두는 번역가이고, 인터프리터는 옆에서 바로바로 통역하는 통역사다.

## 헷갈리기 쉬운 점
- 컴파일러는 언어가 아니라 번역해주는 프로그램이다.
- VS Code가 컴파일해주는 게 아니다. VS Code는 코드를 쓰는 에디터다.
- 컴파일은 암호화가 아니다. 번역하면서 사람이 붙인 이름과 주석이 사라질 뿐이라, 거꾸로 분석할 수 있다 → [[리버스 엔지니어링]]

## 웹 개발에서는
- `npm run build`를 하면 트랜스파일과 파일 묶기(번들링)가 같이 일어난다. 빌드 에러의 상당수는 이 번역 단계에서 "문법이 틀렸다"고 알려주는 것이다.
