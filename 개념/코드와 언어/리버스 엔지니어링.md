# 리버스 엔지니어링

> 완성된 프로그램을 거꾸로 분석해서 어떻게 만들어졌는지, 어떻게 동작하는지 알아내는 일. 역설계라고도 한다.

## 설명
프로그램을 만드는 방향과 반대로 간다.

```
만들 때:     소스 코드 → 컴파일 → 기계어(실행 파일)
역설계할 때: 기계어 → 디스어셈블(어셈블리어) → 디컴파일(소스 코드 비슷한 것)
```

- **디스어셈블**: [[기계어]]를 어셈블리어로 바꿔 읽기.
- **디컴파일**: 기계어나 중간 코드를 소스 코드 비슷한 형태로 되돌리기.
- [[컴파일러]]가 번역하면서 변수 이름, 주석, 원래 구조 같은 사람용 정보가 사라진다. 그래서 디컴파일한 결과는 `FUN_00401a20`, `var_1` 같은 의미 없는 이름투성이고, 사람이 하나하나 읽고 이름을 붙여야 했다.
- 대표 도구: Ghidra·IDA(디컴파일러), JADX(안드로이드 앱), 브라우저 개발자 도구(웹사이트).

### 암호화·난독화와 다른 점
| | 무엇을 한 것인가 | 되돌릴 수 있나 |
|---|---|---|
| 컴파일 | 사람용 코드를 기계어로 번역 | 비슷하게는 되돌릴 수 있다. 원래 이름과 주석은 못 살린다 |
| 난독화 | 코드를 일부러 읽기 어렵게 섞음 | 시간이 들지만 풀 수 있다 |
| 암호화 | 열쇠(키)로 잠금 | 열쇠 없이는 사실상 못 푼다 |

리버스 엔지니어링은 주로 컴파일되거나 난독화된 코드를 다룬다. 암호를 푸는 기술이 아니다.

### AI와 리버스 엔지니어링: REA
2026년에 화제가 된 **REA(Reverse Engineer Anything)** 는 Claude Code, Codex 같은 코딩 AI 에이전트가 Ghidra·IDA 같은 분석 도구를 대신 돌리게 해주는 오픈소스 도구다. [[MCP]]로 AI와 분석 도구를 잇는다 → [[2026-10-31 리버스 엔지니어링과 REA]]

## 비유
완성된 요리를 맛보고 분해해서 레시피를 추측하는 일. 재료와 순서는 알아낼 수 있지만, 셰프가 레시피에 적어둔 메모(주석)까지는 알 수 없다.

## 헷갈리기 쉬운 점
- 디컴파일하면 원래 소스 코드가 그대로 나오는 게 아니다. 동작이 같은 "비슷한 코드"가 나온다.
- 분석할 권한이 있는 프로그램에만 해야 한다. 남의 프로그램을 베끼면 저작권·약관 문제가 생긴다.

## 웹 개발에서는
- 웹사이트의 [[JavaScript]]는 기계어로 컴파일되지 않고 브라우저로 그대로 전송된다. 그래서 개발자 도구(F12 → Sources)에서 누구나 코드를 볼 수 있다. 빌드할 때 코드를 압축(minify)해서 읽기 어렵게 만들 뿐이다.
- 이런 이유로 프론트엔드 코드에 API 키나 비밀번호를 넣으면 안 된다. 비밀 값은 서버 쪽 [[환경 변수]]에 둔다.
