# 빌드

> 사람이 쓴 코드를 실제 서비스에 올릴 수 있는 형태로 바꾸고 묶는 과정.

## 설명
- 개발할 때 쓰는 코드는 사람이 읽고 고치기 편한 모양이다. 그대로 올리면 느리거나, [[브라우저]]가 이해하지 못하는 문법이 섞여 있다.
- 빌드는 이 코드를 정리해서 결과물 폴더를 만든다.

| 빌드에서 하는 일 | 예 |
|---|---|
| 번역 | TypeScript·JSX를 브라우저가 아는 [[JavaScript]]로 → [[컴파일러]] |
| 묶기 (번들링) | 파일 수백 개를 몇 개로 합치기 |
| 줄이기 (압축) | 공백·긴 이름을 줄여 파일 크기 줄이기 |
| 미리 만들기 | 페이지 HTML을 미리 만들어 두기 |

- Next.js 프로젝트는 `npm run build`로 빌드하고, 결과물은 `.next` 폴더에 생긴다.

## 비유
요리를 포장 판매용으로 만드는 일. 주방(개발)에서는 재료를 늘어놓고 맛보며 만들지만, 손님에게 보낼 때는 1인분씩 담고 포장해서 내보낸다.

## 헷갈리기 쉬운 점
- `npm run dev`([[개발 서버]])는 빌드를 하지 않고 바로 보여 준다. 그래서 개발 중에는 잘 되다가 빌드할 때 처음 에러가 나기도 한다.
- 빌드는 [[배포]]의 한 단계다. 빌드 → 결과물을 서버에 올리기 → 공개 순서다.
- 빌드 결과물은 언제든 다시 만들 수 있어서 [[깃이그노어]]에 넣고 커밋하지 않는다.

## 웹 개발에서는
- [[버셀]]은 [[푸시와 풀|푸시]]할 때마다 자기 서버에서 빌드한다. 빌드가 실패하면 사이트는 이전 버전 그대로 남는다.
- 배포 전에 내 컴퓨터에서 `npm run build`를 한 번 돌려 보면, 배포 실패를 미리 잡을 수 있다.
- 빌드 서버는 대부분 [[리눅스]]라서 파일 이름 대소문자가 다르면 내 컴퓨터에서는 되는데 빌드에서 실패할 수 있다.

## 관련 개념
- [[컴파일러]]: 빌드 안에서 일어나는 번역
- [[버셀]]: 푸시하면 대신 빌드해 주는 곳
- [[웹 호스팅]]: 빌드 결과물을 올려 두는 곳
- [[Node.js]]: 빌드 명령을 실행하는 프로그램
- [[개발 서버]]: 빌드 없이 바로 보여 주는 개발용 서버
