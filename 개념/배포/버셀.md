# 버셀

> [[깃허브]] 저장소를 연결해 두면, 푸시할 때마다 자동으로 [[빌드]]해서 인터넷에 공개해 주는 [[웹 호스팅]] 서비스.

## 설명
- 버셀(Vercel)은 Next.js를 만든 회사의 호스팅 플랫폼이다. 개인 비영리 프로젝트는 무료 요금제(Hobby)로 쓸 수 있다.
- 한 번 연결해 두면 흐름이 자동이다.

```
git push ──▶ 깃허브 ──▶ 버셀이 감지 ──▶ 빌드 ──▶ 공개
```

| 배포 종류 | 언제 | 주소 |
|---|---|---|
| 프로덕션 | 기본 브랜치(`main`)에 들어왔을 때 | 실제 사이트 주소 (`프로젝트.vercel.app`, 연결한 [[도메인]]) |
| 미리보기 | 다른 [[브랜치]]나 [[풀 리퀘스트]]에 푸시했을 때 | 브랜치마다 따로 생기는 임시 주소 |

- 대시보드에서 하는 일: 배포 기록과 빌드 로그 보기, [[환경 변수]] 넣기, 도메인 연결, 예전 배포로 되돌리기.

## 비유
자동 인쇄소. 원고(코드)를 공유 폴더(깃허브)에 넣으면 인쇄소가 알아서 책으로 찍어(빌드) 서점에 진열한다(공개). 시안(미리보기)도 따로 뽑아 준다.

## 헷갈리기 쉬운 점
- 버셀은 깃허브의 코드를 가져다 쓴다. 그래서 푸시하지 않은 변경은 반영되지 않는다.
- 내 컴퓨터의 `.env`는 깃허브에 안 올라가기 때문에 버셀에도 없다. 버셀 설정에 환경 변수를 따로 넣어야 한다. "로컬에선 되는데 배포하면 안 돼요"의 단골 원인이다.
- 저장소 안에서 사이트 코드가 하위 폴더에 있으면, 프로젝트 설정의 Root Directory를 그 폴더로 지정해야 한다.

## 웹 개발에서는
- 워크숍 협업 방식: 깃허브 저장소 + 버셀 연결. 브랜치에서 작업하고 PR을 열면 미리보기 주소가 생기고, `main`에 [[병합]]하면 실제 사이트가 바뀐다.
- 빌드가 실패하면 버셀 대시보드의 빌드 로그에서 원인을 찾는다. 사이트는 이전 버전 그대로 유지된다.
- 비슷한 서비스로 Netlify, Cloudflare Pages가 있다.
