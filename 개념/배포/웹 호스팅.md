# 웹 호스팅

> 내 웹사이트 파일을 올려두고 24시간 켜두는 남의 컴퓨터(서버)를 빌려 쓰는 것.

## 설명
- 웹사이트는 누가 언제 들어올지 모르기 때문에 서버가 항상 켜져 있어야 한다. 내 노트북을 24시간 켜둘 수는 없으니, 서버를 가진 회사의 컴퓨터를 빌린다.

| 종류 | 설명 | 예 |
|---|---|---|
| 플랫폼형 | Git에 올리면 [[빌드]]·배포·HTTPS까지 알아서 해줌 | [[버셀\|Vercel]], Netlify |
| 정적 호스팅 | HTML·CSS·JS 파일만 올려서 보여줌 | [[깃허브\|GitHub]] Pages |
| 클라우드 서버 | 빈 컴퓨터를 통째로 빌려서 직접 설치·관리 | AWS, Google Cloud |
| 웹 호스팅 상품 | 한 서버를 여러 사람이 나눠 씀. 워드프레스 등 | 카페24, 가비아 |

## 비유
가게 임대. [[도메인]]이 간판(주소)이라면, 호스팅은 가게 자리를 빌리는 것이다. 간판만 있고 가게가 없으면 손님이 와도 볼 게 없다.

## 헷갈리기 쉬운 점
- 도메인과 호스팅은 따로다. 도메인은 이름만, 호스팅은 자리만 빌린 것이다. 둘을 [[DNS]]로 이어야 내 주소로 내 사이트가 열린다.
- "배포"는 내 파일을 호스팅 서버에 올려서 공개하는 행동이고, "호스팅"은 그 서버를 빌려 쓰는 서비스다.

## 웹 개발에서는
- 워크숍에서는 Vercel을 쓴다. GitHub에 코드를 올리면 Vercel이 자동으로 빌드해서 `프로젝트이름.vercel.app` 주소로 공개한다.
- 내 컴퓨터의 `.env`는 따라가지 않기 때문에, Vercel 설정에 [[환경 변수]]를 따로 넣어야 한다.
- 호스팅 서버는 대부분 [[리눅스]]라서 파일 이름 대소문자를 구분한다.

## 관련 개념
- [[서버]]: 호스팅으로 빌리는 것
- [[도메인]] · [[DNS]]: 호스팅과 짝을 이루는 주소
- [[환경 변수]]: 호스팅 설정에 따로 넣는 값
- [[리눅스]]: 호스팅 서버의 OS
- [[버셀]]: 워크숍에서 쓰는 호스팅 플랫폼
- [[빌드]]: 호스팅에 올리기 전에 결과물을 만드는 과정
