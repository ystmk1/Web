# 바인딩

> Cloudflare Worker 설정에 "이 저장소를 이 이름으로 연결해"라고 적어서, 키 없이 코드에서 바로 쓰게 하는 방식.

## 설명
- `wrangler.toml`(또는 `wrangler.jsonc`)에 버킷·DB 이름과 코드에서 부를 이름을 적는다.
  ```toml
  [[r2_buckets]]
  binding = "MEDIA"
  bucket_name = "portfolio-media"
  ```
- 그러면 Worker 코드에서 `env.MEDIA.put(...)`, `env.MEDIA.get(...)`처럼 바로 쓴다.
- Worker와 저장소가 둘 다 Cloudflare 안에 있어서, Cloudflare가 "이 Worker는 이 버킷을 써도 된다"를 직접 보증한다. 그래서 Access Key나 Secret이 필요 없다.
- R2뿐 아니라 D1(데이터베이스), KV(작은 저장소)도 같은 방식으로 붙인다.

## 비유
외부 사람(Vercel 같은 다른 회사 서버)은 출입증(키)을 받아야 창고에 들어가지만, 같은 건물 직원(Worker)은 사원증에 "3층 창고 출입 가능"이 이미 등록돼 있어서 따로 열쇠가 없다.

## 헷갈리기 쉬운 점
- 바인딩은 Cloudflare 안에서만 된다. [[버셀]]에서 돌아가는 Next.js 코드는 바인딩을 못 쓰고, R2 키를 [[환경 변수]]로 받아야 한다.
- 바인딩 이름(`MEDIA`)은 코드에서 부르는 별명이고, 실제 버킷 이름(`portfolio-media`)과 달라도 된다.

## 웹 개발에서는
- 포트폴리오 댓글 Worker가 D1을 `env.DB` 바인딩으로 쓴다. 그래서 Vercel에는 댓글 DB 키가 없고 Worker 주소만 넣는다.
- 가능하면 키를 여기저기 나눠 주기보다, Cloudflare 안에서 바인딩으로 처리하는 쪽이 안전하다.
