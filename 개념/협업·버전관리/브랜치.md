# 브랜치

> 기록을 갈래로 나누는 것. 원본을 건드리지 않고 다른 갈래에서 새 기능을 만들어 볼 수 있다.

## 설명
- 모든 [[저장소]]에는 기본 브랜치가 하나 있다. 요즘 [[깃허브]]는 기본 이름을 `main`으로 쓴다. 예전 저장소에는 `master`라는 이름이 남아 있기도 하다.
- 새 기능을 만들 때는 `main`에서 갈래를 하나 뻗는다. 그 갈래에 [[커밋]]을 쌓아도 `main`은 그대로다.
- 다 만들면 갈래를 다시 `main`에 합친다 → [[병합]]

```
main      ●──●──────────●  (합친 뒤)
              \        /
login-page     ●──●──●
```

- 브랜치는 복사본이 아니라 "커밋 줄의 어디를 가리키는지"를 적은 이름표다. 그래서 만들고 지우는 것이 빠르고 가볍다.

## 비유
평행 세계. 원래 세계(`main`)는 그대로 두고, 다른 세계에서 실험한다. 실험이 성공하면 두 세계를 합치고, 실패하면 그 세계를 버리면 된다.

## 헷갈리기 쉬운 점
- 브랜치를 바꾸면(`git switch`) 폴더 안의 파일 내용이 그 브랜치 상태로 바뀐다. 파일이 사라진 것처럼 보여도 다른 브랜치에 있는 것이다.
- 브랜치는 폴더가 아니다. 같은 폴더 안에서 갈래만 바뀐다.
- 내 컴퓨터에 만든 브랜치는 [[푸시와 풀|푸시]]해야 깃허브에도 생긴다.

## 웹 개발에서는
- `main`은 실제로 공개된 사이트와 같은 상태로 둔다. 기능 작업은 항상 브랜치에서 하고 [[풀 리퀘스트]]로 합친다.
- 브랜치 이름은 하는 일을 적는다. 예: `login-page`, `fix-header`.
- [[버셀]]은 브랜치마다 미리보기 주소를 따로 만들어 준다. `main`에 합치기 전에 결과를 볼 수 있다.

## 관련 개념

- [[병합]]: 브랜치를 다시 합치기
- [[풀 리퀘스트]]: 깃허브에서 브랜치를 합쳐 달라고 요청하기
- [[충돌]]: 합칠 때 같은 곳을 다르게 고친 경우
