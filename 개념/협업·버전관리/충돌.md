# 충돌

> 두 갈래에서 같은 파일의 같은 부분을 서로 다르게 고쳐서, [[깃]]이 어느 쪽을 살릴지 혼자 정하지 못하는 상태.

## 설명
- [[병합]]이나 [[푸시와 풀|풀]]을 할 때 생긴다. 깃은 충돌한 파일에 두 버전을 모두 적어 두고 사람에게 고르라고 한다.

```
<<<<<<< HEAD
버튼 색: 파랑      ← 지금 내 쪽
=======
버튼 색: 빨강      ← 합치려는 쪽
>>>>>>> login-page
```

- 고치는 순서
  1. 표시(`<<<<<<<`, `=======`, `>>>>>>>`)가 있는 파일을 연다.
  2. 남길 내용만 두고 표시 줄을 모두 지운다. 둘 다 섞어서 새로 써도 된다.
  3. 저장하고 [[커밋]]한다.
- VS Code는 충돌 부분에 "Accept Current / Accept Incoming / Accept Both" 버튼을 보여 준다.

## 비유
두 사람이 같은 문서의 같은 문장을 동시에 고친 상황. 편집자가 둘 중 하나를 고르거나, 두 문장을 합쳐서 새로 써야 한다.

## 헷갈리기 쉬운 점
- 충돌은 고장이 아니다. 같이 일하면 자연스럽게 생기는 일이고, 고르기만 하면 끝난다.
- 같은 파일을 둘 다 고쳐도 서로 다른 줄이면 충돌이 나지 않는다. 깃이 자동으로 합친다.
- 표시 줄(`<<<<<<<`)을 지우지 않고 커밋하면 코드가 깨진다. 꼭 다 지웠는지 확인한다.

## 웹 개발에서는
- 충돌을 줄이려면 [[브랜치]]를 짧게 유지하고, 작업 전에 `main`을 자주 받아온다(풀).
- 여러 명이 같은 파일(예: 전체 레이아웃 파일)을 고치면 충돌이 잦다. 작업을 파일 단위로 나누면 좋다.
- AI 코딩 에이전트에게 "충돌 해결해줘"라고 맡길 수 있다. 다만 어느 쪽을 살렸는지는 직접 확인한다.
