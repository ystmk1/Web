# 깃이그노어

> [[깃]]이 기록하지 않고 무시할 파일과 폴더를 적어 두는 설정 파일. 파일 이름은 `.gitignore`다.

## 설명
- [[저장소]] 맨 위에 `.gitignore` 파일을 만들고 한 줄에 하나씩 적는다.

```
node_modules/
.next/
.env*
.DS_Store
```

- 여기 적힌 파일은 `git add`를 해도 [[커밋]]에 담기지 않는다. 그래서 [[깃허브]]에도 올라가지 않는다.
- 주로 넣는 것

| 무엇 | 왜 |
|---|---|
| `node_modules/` | `npm install`로 언제든 다시 받을 수 있는 수만 개의 파일 |
| `.next/`, `dist/` | [[빌드]]하면 다시 생기는 결과물 |
| `.env` | API 키 같은 비밀 값 → [[환경 변수]] |
| `.DS_Store`, `Thumbs.db` | 운영체제가 만드는 잡파일 |

## 비유
택배 보낼 때 "이건 넣지 마세요" 목록. 상자(커밋)를 쌀 때 목록에 있는 물건은 자동으로 빠진다.

## 헷갈리기 쉬운 점
- **이미 커밋된 파일은 나중에 적어도 계속 기록된다.** `.env`를 실수로 한 번 올렸다면, 목록에 넣는 것만으로는 깃허브에서 사라지지 않는다. 기록에서 빼는 작업을 따로 하고, 새어 나간 키는 새로 발급받는다.
- 이름이 점(.)으로 시작해서 파일 탐색기나 일부 도구에서 숨김 파일로 보인다.
- 프로젝트를 새로 만들면 Next.js 같은 도구가 기본 `.gitignore`를 만들어 준다. 지우지 않는다.

## 웹 개발에서는
- `.env`를 깃허브에 올리는 사고가 가장 흔하다. 공개 저장소면 몇 분 안에 키가 악용될 수 있다.
- `.env`는 깃허브에 안 올라가기 때문에 [[버셀]] 같은 배포 서비스에는 환경 변수를 따로 넣어야 한다.

## 관련 개념
- [[깃]]: 이 목록을 읽는 프로그램
- [[환경 변수]]: `.env`를 무시해야 하는 이유
- [[빌드]]: 빌드 결과물은 무시 목록에 넣는다
- [[커밋]]: 무시된 파일은 커밋에 담기지 않는다
