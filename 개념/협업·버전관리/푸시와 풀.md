# 푸시와 풀

> 푸시는 내 컴퓨터의 [[커밋]]을 원격 [[저장소]]로 올리는 것, 풀은 원격 저장소의 새 커밋을 내 컴퓨터로 받아오는 것.

## 설명
- [[깃]]의 기록은 내 컴퓨터(로컬)와 [[깃허브]](원격)에 따로 있다. 둘을 맞추는 방법이 푸시와 풀이다.

```
내 컴퓨터 ──push──▶ 깃허브
          ◀──pull──
```

| | 방향 | 명령어 |
|---|---|---|
| 푸시 | 로컬 → 원격 | `git push` |
| 풀 | 원격 → 로컬 | `git pull` |
| 페치 | 원격 → 로컬 (확인만, 합치지 않음) | `git fetch` |

- 풀은 "받아오기(fetch) + 합치기([[병합]])"를 한 번에 하는 명령이다.

## 비유
공유 노트와 내 수첩. 내 수첩에 쓴 것을 공유 노트에 옮겨 적는 것이 푸시, 공유 노트에 새로 생긴 내용을 내 수첩에 옮겨 오는 것이 풀이다.

## 헷갈리기 쉬운 점
- 커밋만 하고 푸시를 안 하면 깃허브에는 아무것도 안 올라간다. 팀원도, [[버셀]]도 내 변경을 모른다.
- 원격에 내가 모르는 새 커밋이 있으면 푸시가 거절된다. 먼저 풀해서 합친 뒤 다시 푸시한다.
- 풀할 때 같은 줄을 서로 고쳤다면 [[충돌]]이 난다.
- [[풀 리퀘스트]]의 "풀"과는 다른 것이다.

## 웹 개발에서는
- 작업 시작 전에 풀, 작업 끝나면 커밋하고 푸시. 이 습관이 충돌을 줄인다.
- 깃허브에 푸시하면 연결된 버셀이 자동으로 [[빌드]]와 배포를 시작한다.
- VS Code 아래쪽 상태 표시줄의 동기화 버튼(↓↑)은 풀과 푸시를 한 번에 한다.

## 관련 개념
- [[커밋]]: 푸시하는 대상
- [[저장소]]: 로컬 저장소와 원격 저장소
- [[충돌]]: 풀할 때 생길 수 있는 문제
- [[버셀]]: 푸시하면 자동 배포되는 곳
