# 병합

> 다른 [[브랜치]]에서 한 작업을 지금 브랜치에 합치는 것. 영어로 머지(merge)라고 한다.

## 설명
- 갈래로 나눠 작업한 [[커밋]]들을 하나로 모으는 일이다. 보통 기능 브랜치를 `main`에 합친다.
- [[깃]]이 두 갈래에서 바뀐 부분을 자동으로 비교해서 합친다.
  - 서로 다른 파일이나 다른 줄을 고쳤다면 자동으로 합쳐진다.
  - 같은 파일의 같은 줄을 서로 다르게 고쳤다면 깃이 멈추고 사람에게 물어본다 → [[충돌]]
- [[깃허브]]의 [[풀 리퀘스트]] 화면에서 "Merge" 버튼으로 합치는 경우가 가장 많다. 이때 합치는 방식을 고를 수 있다.

| 방식 | 결과 |
|---|---|
| Merge commit | 브랜치 기록을 그대로 두고, "합쳤다"는 커밋을 하나 더 만든다 |
| Squash and merge | 브랜치의 커밋 여러 개를 하나로 뭉쳐서 합친다 |
| Rebase and merge | 브랜치의 커밋들을 `main` 끝에 한 줄로 이어 붙인다 |

## 비유
문서를 나눠 쓴 뒤 하나로 합치기. 각자 다른 장을 썼다면 붙이기만 하면 된다. 같은 문단을 둘 다 고쳤다면 어느 쪽을 살릴지 정해야 한다.

## 헷갈리기 쉬운 점
- 병합은 방향이 있다. "A를 B에 합친다"는 B에 A의 변경이 들어간다는 뜻이다. A는 그대로다.
- 합친 뒤에도 기능 브랜치는 남아 있다. 다 쓴 브랜치는 지워도 기록은 `main`에 남는다.
- [[풀 리퀘스트]]는 "합쳐 주세요"라는 요청이고, 병합은 실제로 합치는 행동이다.

## 웹 개발에서는
- `main`에 병합되면 [[버셀]]이 그 상태로 다시 [[빌드]]해서 실제 사이트에 반영한다. 그래서 병합 = 배포인 경우가 많다.
- 병합하기 전에 브랜치의 미리보기 사이트에서 결과를 확인한다.

- [[풀 리퀘스트]]: 병합 전에 리뷰하는 곳
