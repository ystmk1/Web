# 풀 리퀘스트

> 내 [[브랜치]]의 변경을 `main`에 합쳐 달라고 [[깃허브]]에 올리는 요청. 줄여서 PR이라고 한다.

## 설명
- 깃 자체 기능이 아니라 깃허브 같은 서비스의 기능이다. GitLab에서는 머지 리퀘스트(MR)라고 부른다.
- PR 화면에서 할 수 있는 일

| 할 일 | 설명 |
|---|---|
| 바뀐 내용 보기 | 파일별로 지운 줄(빨강)과 더한 줄(초록)을 보여준다 |
| 리뷰 | 줄마다 댓글을 달고, 승인하거나 수정을 요청한다 |
| 자동 검사 | [[버셀]] 미리보기, 빌드 성공 여부 등이 표시된다 |
| 충돌 확인 | `main`과 [[충돌]]이 있으면 미리 알려준다 |
| 합치기 | "Merge" 버튼으로 [[병합]]한다 |

- 흐름: 브랜치에서 [[커밋]] → [[푸시와 풀|푸시]] → 깃허브에서 PR 만들기 → 리뷰·확인 → 병합

## 비유
결재 서류. 내가 작업한 내용을 올리면, 팀장이 읽어 보고 의견을 달거나 도장을 찍는다. 도장이 찍히면 공식 문서(`main`)에 반영된다.

## 헷갈리기 쉬운 점
- 이름에 "풀(pull)"이 있지만, [[푸시와 풀|풀]](받아오기)과는 다른 것이다. "내 변경을 당겨가 주세요(pull)"라는 요청이라는 뜻이다.
- PR을 만들어도 아직 합쳐진 게 아니다. 병합 버튼을 눌러야 `main`이 바뀐다.
- PR을 연 뒤에도 같은 브랜치에 커밋을 더 푸시하면 PR에 자동으로 추가된다.

## 웹 개발에서는
- 혼자 작업해도 PR을 쓰면 좋다. 무엇을 바꿨는지 한눈에 보이고, 버셀 미리보기로 결과를 먼저 확인할 수 있다.
- 워크숍 협업 방식: 새 기능은 브랜치에서 만들고 PR로 `main`에 합친다.
- PR 제목과 설명은 나중에 "이 기능 언제 들어왔지?"를 찾을 때 기록이 된다.
