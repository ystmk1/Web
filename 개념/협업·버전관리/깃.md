# 깃

> 파일이 바뀐 기록을 시점별로 저장해 두는 프로그램. 언제든 예전 상태로 돌아가거나, 여러 명이 고친 내용을 합칠 수 있다.

## 설명
- 깃(Git)은 **버전 관리 시스템**이다. 2005년에 [[리눅스]]를 만든 리누스 토르발스가 만들었다.
- 내 컴퓨터에 설치해서 쓰는 프로그램이다. 인터넷이 없어도 동작한다.
- 깃으로 관리하는 폴더를 [[저장소]]라고 한다. 그 안에 숨겨진 `.git` 폴더가 생기고, 모든 기록이 여기에 쌓인다.
- 기록은 [[커밋]] 단위로 남는다. "이 시점의 파일 상태 + 무엇을 바꿨는지 메모"가 커밋 하나다.

| 하는 일 | 명령어 예 |
|---|---|
| 폴더를 깃으로 관리 시작 | `git init` |
| 바뀐 파일을 담기 | `git add` |
| 기록 남기기 | `git commit -m "메시지"` |
| 갈래 만들기 | `git branch`, `git switch` |
| 원격에 올리기·받기 | `git push`, `git pull` |

## 비유
게임의 세이브 포인트. 중요한 순간마다 저장해 두면, 망쳐도 그 시점으로 돌아갈 수 있다. 깃은 세이브마다 "무엇을 했는지" 메모까지 남겨 준다.

## 헷갈리기 쉬운 점
- **깃 ≠ [[깃허브]].** 깃은 내 컴퓨터의 기록 프로그램이고, 깃허브는 깃 저장소를 인터넷에 올려두는 웹 서비스다. 깃은 깃허브 없이도 쓸 수 있다.
- "파일명_최종_진짜최종.psd"처럼 파일을 복사해 두는 방식과 다르다. 깃은 파일 하나만 남기고, 바뀐 기록은 따로 저장한다.
- 깃은 주로 코드 같은 텍스트 파일에 강하다. 큰 이미지·영상은 바뀐 부분을 비교하기 어렵다.

## 웹 개발에서는
- 바이브코딩에서 특히 중요하다. AI가 코드를 망가뜨려도 마지막 [[커밋]]으로 되돌리면 된다.
- 보통 [[터미널]]에서 `git` 명령어로 쓰거나, VS Code의 소스 제어 탭을 누른다. AI 코딩 에이전트에게 "커밋해줘"라고 시켜도 된다.
- 깃이 무시할 파일은 [[깃이그노어]]에 적는다.
