# 기존 코드에 깃 연결하기

> 저장소를 만들기 전에 먼저 작업해버린 코드가 있을 때, 그 폴더를 기준으로 [[깃]]을 시작하는 방법.

## 설명
- 순서를 거꾸로 했어도 문제없다. [[저장소]]는 "먼저 만들고 코드를 넣는 것"이 아니라 "지금 있는 폴더를 깃이 추적하게 만드는 것"이라 어느 시점에 시작해도 된다.
- 작업 폴더에서 `git init`을 하면 그 폴더가 로컬 저장소가 된다. 이미 있던 파일은 그대로 두고 기록만 새로 시작한다.

## 순서
1. **폴더부터 통째로 복사해서 백업해둔다.** (`git init` 자체는 안전하지만, 바로 이어서 할 `.gitignore` 정리나 add/commit 과정에서 실수로 원치 않는 파일을 지우거나 덮어쓸 수 있어서, 되돌릴 방법을 먼저 만들어두는 습관이다.)
2. 작업 폴더에서 `git init`
3. [[깃이그노어]](`.gitignore`)부터 만들어서 `node_modules`, `.env` 같은 걸 빼놓는다.
4. `git add .` → `git commit -m "첫 커밋"`
5. 깃허브에서 **완전히 빈 저장소**를 만든다 (README, .gitignore, license 전부 체크 해제)
6. `git remote add origin <저장소 주소>`
7. `git push -u origin main`

## 비유
이사 다 하고 나서 "이 집 등기부터 떼자"고 하는 것과 비슷하다. 순서는 바뀌었지만 지금 있는 걸 기준으로 서류(기록)를 새로 만들면 된다.

## 헷갈리기 쉬운 점
- 깃허브에서 저장소를 만들 때 README를 자동으로 체크해서 만들면, 원격에 이미 커밋이 하나 생긴 상태라 내 로컬과 "기록이 다른 곳에서 시작된" 상태가 된다. 이때 `git push`가 거절된다. 완전히 빈 저장소로 만들거나, `git pull origin main --allow-unrelated-histories`로 두 기록을 합쳐야 한다.
- 이 상황에서는 깃허브 → 로컬([[클론]])이 아니라 **로컬 → 깃허브** 방향이다. 로컬 폴더가 원본, 원격은 아직 빈 깡통이다.
- 백업은 "되돌릴 방법"이지 "깃이 필요로 하는 절차"가 아니다. 깃 자체는 add/commit 전 파일을 함부로 지우지 않지만, 사람이 명령어를 잘못 치는 경우에 대비하는 것이다.

## 웹 개발에서는
- AI 코딩 에이전트에게 시킬 때는 "이 폴더를 기준으로"라는 말을 꼭 넣는 게 좋다. 안 그러면 새 폴더를 만들거나 다른 템플릿을 받아올 수도 있다.
- 예시 요청: "지금 이 폴더에 있는 코드를 기준으로 깃 초기화하고, 깃허브에 새 저장소 만들어서 그대로 push해줘. 원격은 비어있으니까 pull은 필요 없어."
