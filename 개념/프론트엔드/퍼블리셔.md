# 퍼블리셔

> 디자이너가 만든 화면 시안을 [[HTML]]과 [[CSS]]로 실제 웹 페이지로 옮기는 직무. 한국 IT 업계에서 흔히 쓰는 직무 이름이다.

## 설명
- 디자이너는 그림 파일로 화면을 설계한다. 이 그림은 브라우저에서 열 수 없다. 퍼블리셔는 이 그림을 보고 브라우저가 읽을 수 있는 코드로 바꾼다.
- 주로 하는 일은 세 가지다.
  - HTML로 화면의 구조를 만든다.
  - CSS로 색, 글자, 간격, 배치를 시안과 똑같이 맞춘다.
  - 화면 크기가 바뀌어도 깨지지 않게 만든다. 폰, 태블릿, 노트북에서 모두 잘 보여야 한다.
- 여러 [[브라우저]]에서 같은 모습으로 보이는지 확인한다 → [[크로스 브라우징]]
- 시각장애인도 화면을 쓸 수 있게 코드를 정리하는 일도 한다. 이것을 웹 접근성이라고 한다.
- 간단한 움직임을 넣을 때는 [[JavaScript]]를 조금 쓰기도 한다.

| 단계 | 담당 | 결과물 |
|---|---|---|
| 화면 설계 | 디자이너 | 시안 (그림 파일) |
| 화면 코드로 옮기기 | 퍼블리셔 | HTML, CSS 파일 |
| 기능 붙이기 | 프론트엔드 개발자 | 동작하는 [[웹 페이지]] |

## 비유
건축 도면을 보고 실제 건물의 뼈대와 인테리어를 만드는 시공팀. 디자이너가 도면(시안)을 그리면, 퍼블리셔가 벽을 세우고 색을 칠해서 눈에 보이는 건물로 만든다. 건물 안의 전기와 수도 같은 기능은 개발자가 이어서 설치한다.

## 헷갈리기 쉬운 점
- **퍼블리셔와 프론트엔드 개발자의 경계는 회사마다 다르다.** 어떤 회사는 퍼블리셔가 HTML과 CSS만 맡는다. 어떤 회사는 퍼블리셔가 JavaScript까지 맡는다. 직무 이름만 보고 하는 일을 단정하지 않는 것이 좋다.
- **퍼블리셔는 디자이너가 아니다.** 시안을 새로 그리지 않고, 만들어진 시안을 코드로 옮긴다.
- **퍼블리셔라는 이름은 한국에서 특히 많이 쓴다.** 해외에서는 같은 일을 프론트엔드 개발자가 하는 경우가 많다.
- **바이브코딩 시대에도 필요한 감각이다.** AI가 HTML과 CSS를 써주더라도, 시안과 맞는지 판단하는 눈은 사람이 가져야 한다.

## 웹 개발에서는
- 동아리 프로젝트에서 디자인 시안을 코드로 옮기는 사람이 곧 퍼블리셔 역할을 한다. 직함이 없어도 이 일은 반드시 필요하다.
- AI에게 화면을 시킬 때도 퍼블리싱 지식이 도움이 된다. "버튼 간격을 16px로 줄여줘"처럼 CSS 용어로 말하면 원하는 결과를 빨리 얻는다.
- 브라우저의 개발자 도구로 다른 사이트의 HTML과 CSS를 열어 보면 퍼블리싱 연습이 된다.
- 퍼블리셔가 만든 파일은 기능 개발자가 이어받아 데이터와 연결한다. 그래서 이름과 구조를 깔끔하게 정리해 두어야 한다.

## 관련 개념

- [[CSS]]: 화면을 꾸미는 언어

- [[크로스 브라우징]]: 어떤 브라우저에서도 같게 보이게 하는 일
- [[웹 페이지]]: 퍼블리셔가 만드는 결과물
