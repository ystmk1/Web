# 영상 최적화

> 웹에 영상을 넣을 때 느려지지 않게 하는 방법들. 핵심은 "직접 올릴지, 전문 서비스에 맡길지"를 먼저 정하는 것.

## 설명
웹에 영상을 넣는 방법은 두 가지다.
- **직접 호스팅**: `<video src="/intro.mp4">` 처럼 영상 파일을 사이트에 직접 올려서 재생. 짧고 가벼운 장식용 루프에 적합.
- **외부 서비스 임베드**: YouTube·Vimeo·Cloudflare Stream 같은 전용 서비스에 올리고 `<iframe>`으로 불러오기. 긴 영상, 품질이 중요한 콘텐츠에 적합.

## 느려지지 않게 하는 방법
- **파일 자체를 작게**: 해상도를 낮추고(720p 안팎) H.264(mp4)로 압축. 배경 루프는 몇 MB 이내로.
- **poster 이미지**: `<video poster="/thumb.jpg">` — 영상이 로드되기 전 썸네일을 먼저 보여줘서 화면이 비지 않게 한다.
- **preload="metadata"**: 영상 전체가 아니라 길이·크기 정보만 먼저 받는다.
- **화면에 보일 때만 로드**: Intersection Observer로 스크롤해서 보일 때 `src`를 넣고 재생 시작. (`loading="lazy"`는 `<img>`·`<iframe>`용이라 `<video>`에는 동작하지 않는다.)
- **faststart**: mp4는 재생 정보(moov)가 파일 맨 앞에 있어야 다 받기 전에 재생이 시작된다. ffmpeg의 `-movflags +faststart` 옵션.
- **긴 영상·고품질 콘텐츠는 직접 호스팅하지 않기**: YouTube·Vimeo·Cloudflare Stream은 사용자 기기·네트워크에 맞춰 화질을 자동으로 낮추는 적응형 스트리밍을 해준다. 직접 호스팅보다 훨씬 안 느리다.

## 유튜브·비메오 없이 직접 보여주기
영상 길이에 따라 방법이 갈린다.

| 상황 | 방법 |
|---|---|
| 30초 이하 루프·작업 클립 | 압축 mp4(+WebM)를 [[Cloudflare R2]]에 올리고 `<video>`로 재생 |
| 1분 넘는 영상, 화질 중요 | HLS로 쪼개서 R2에 올리고 hls.js로 재생 (적응형 스트리밍) |
| 직접 관리하기 싫음 | Cloudflare Stream·Mux·Bunny Stream 같은 유료 영상 호스팅 (로고·추천 영상 없음) |

- 압축 예: `ffmpeg -i 원본.mov -c:v libx264 -crf 23 -preset slow -vf "scale=1920:-2" -an -movflags +faststart out.mp4` (`-an`은 소리 제거, 루프 영상이면 소리가 필요 없다)
- 여러 형식 제공: `<source src="a.webm" type="video/webm">`(더 작음)을 먼저, `<source src="a.mp4" type="video/mp4">`를 뒤에 두면 브라우저가 읽을 수 있는 첫 번째를 쓴다.
- HLS: 영상을 여러 화질 × 몇 초짜리 조각으로 잘라두고, 인터넷 속도에 따라 화질을 바꿔가며 받는 방식. 유튜브가 하는 일을 직접 하는 것이다.

## 홈페이지 배경 영상
- 화면 꽉 채우기: `position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover;` + 내용보다 뒤(`z-index`)에 둔다.
- 글자를 올린다면 반투명 검은 오버레이를 한 겹 깔아 대비를 확보한다.
- 첫 화면이라 lazy load 하지 않는다. 대신 용량을 더 줄인다: 8~15초, 소리 제거, `-crf 26~28`(배경은 화질 손실이 덜 보임), 목표 2~5MB.
- 모바일은 세로로 잘라낸 720p 버전을 따로 만들어 화면 크기에 따라 골라 쓰면 용량이 크게 준다.
- `poster`가 사실상 필수다. iOS 저전력 모드 등에서는 자동재생이 막혀 poster만 보인다.
- 움직임 줄이기 설정(`prefers-reduced-motion`)을 켠 사용자에게는 영상 대신 poster만 보여준다.
- 화면 밖으로 스크롤되거나 탭이 숨겨지면 `pause()` 해서 배터리를 아낀다.
- 장식용이므로 `aria-hidden="true"`로 스크린 리더가 읽지 않게 한다.
- 끊김 없는 루프는 코드가 아니라 편집에서 만든다. 끝과 시작을 크로스페이드하거나 처음과 끝 프레임을 맞춘다.

## 헷갈리기 쉬운 점
- `autoplay`는 `muted`가 같이 있어야 브라우저가 허용한다. 소리 있는 영상의 자동재생은 대부분 막힌다.
- 모바일에서 영상이 전체화면으로 튀는 걸 막으려면 `playsinline` 속성을 붙여야 한다.
- 버셀 같은 호스팅은 작은 코드·이미지 위주로 쓰기 좋게 되어 있다. 큰 영상 파일을 계속 올리면 저장공간·트래픽 비용이 불리해진다 → [[버셀]]

## 웹 개발에서는
- 배경 인트로 영상처럼 짧은 루프: `/public` 폴더에 압축된 mp4를 두고 `<video autoplay muted loop playsinline>`으로 직접 재생.
- 제대로 된 콘텐츠 영상(강의, 인터뷰 등): YouTube 미등록(unlisted) 업로드 후 `<iframe>` 임베드가 가장 간단하고 비용도 안 든다.
