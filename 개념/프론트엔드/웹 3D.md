# 웹 3D

> 3D 모델을 웹 페이지에서 돌아가게 하거나 마우스로 돌려보게 하는 방법. "실시간으로 계산할지, 미리 렌더한 그림을 보여줄지"가 갈림길이다.

## 설명
세 가지 방식이 있다.

| | 실시간 3D (GLB) | 렌더 이미지 시퀀스 | 턴테이블 영상 |
|---|---|---|---|
| 원리 | 브라우저가 매 프레임 직접 그림 (WebGL) | 360°를 36~72장으로 미리 렌더, 드래그하면 사진을 바꿔 보여줌 | 한 바퀴 도는 렌더를 영상으로 |
| 품질 | 실시간 렌더 수준 (유리·굴절·GI 약함) | **렌더 그대로** | **렌더 그대로** |
| 인터랙션 | 자유 회전·줌·색 바꾸기 | 가로 회전 (위아래는 장 수가 크게 늘어남) | 없음 (자동 재생만) |
| 용량 | 모델+텍스처 수 MB (압축 필요) | 장당 100KB 안팎 × 장 수 | 2~5MB |
| 난이도 | 중~상 | 중 | 하 |

### 실시간 3D 도구
- **`<model-viewer>`** (Google): 태그 한 줄. `<model-viewer src="a.glb" auto-rotate camera-controls environment-image="studio.hdr">`. 가장 쉽다.
- **React Three Fiber + drei**: React에서 Three.js를 쓰는 방법. 조명·재질·연출을 세밀하게 조정할 때.
- **Spline**: 디자이너용 3D 툴. 만들고 바로 웹에 임베드.

## 비유
실시간 3D는 무대 위 실제 조각상(어느 방향에서든 볼 수 있지만 조명은 무대 조명 수준), 이미지 시퀀스는 조각상을 스튜디오에서 한 바퀴 돌며 찍은 사진첩, 영상은 그 사진첩을 자동으로 넘기는 것.

## 헷갈리기 쉬운 점
- 실시간 3D는 키샷·블렌더 Cycles 같은 렌더와 같은 품질이 나오지 않는다. 브라우저가 1초에 60번 그려야 하므로 빛 계산을 단순화한다. 특히 **유리·투명·굴절**이 약하다.
- 실시간 품질을 끌어올리는 방법: 조명·그림자를 텍스처에 미리 구워 넣기(베이킹), HDRI 환경맵 쓰기.
- 모델 파일은 **GLB(glTF)** 형식으로 내보내고, Draco·Meshopt로 메쉬를, KTX2/WebP로 텍스처를 압축한다. 압축 안 하면 수십 MB가 되기 쉽다.
- 영상을 마우스 위치로 앞뒤로 감는(scrub) 방식은 버벅이기 쉽다. 그런 인터랙션은 이미지 시퀀스가 낫다.

## 웹 개발에서는
- 천천히 도는 장식이면 → 영상
- 렌더 품질 그대로 마우스로 돌려보기 → 이미지 시퀀스
- 자유롭게 돌리고 확대·재질 변경 → 실시간 GLB (품질 타협)
- 섞어 쓰기: 홈에는 영상, 상세 페이지에서 "3D로 보기"를 누르면 GLB 뷰어.
