# 프로젝트 폴더 구조

> [[Next.js]] 프로젝트에서 역할별로 코드를 정리하는 폴더 관례. `app/` 폴더만 주소([[라우트]])와 연결되고, 나머지는 코드를 어디 둘지 정하는 규칙이다.

## 설명
```
my-app/
├─ src/
│  ├─ app/          → 페이지 (주소) — [[라우트]]
│  ├─ components/   → 화면 부품 (버튼·카드 등, 재사용)
│  ├─ lib/          → 공통 도구 함수 (DB 연결, 날짜 계산 등)
│  ├─ hooks/        → React 동작 재사용
│  └─ types/        → 데이터 모양 정의 (TypeScript)
└─ public/          → 이미지·폰트처럼 가공 없이 그대로 쓰는 파일 (src 밖)
```

- `app/` 안의 하위 폴더만 주소와 연결된다. `login/` = `/login`, `dashboard/` = `/dashboard`.
- `components`, `lib`, `hooks`, `types`는 주소와 무관하다. 프로젝트가 커질수록 파일을 찾기 쉽게 역할별로 나눈 정리 방식일 뿐이다.
- `public/`은 `src/` 바깥에 둔다. 코드가 아니라 그대로 서빙되는 자산이기 때문이다.

## 헷갈리기 쉬운 점
- 폴더 구조는 [[DOM]]과 무관하다. 전부 서버 쪽 프로젝트 정리·라우팅 얘기다.
- `app/`만 "라우팅 규칙"을 따르고, 나머지는 "정리 관례"다. 둘을 같은 규칙으로 착각하기 쉽다.

## 관련 개념
- [[라우트]]: `app/` 폴더가 따르는 규칙
- [[컴포넌트]]: `components/`에 모아두는 것
- [[Next.js]]: 이 구조를 쓰는 프레임워크
