# MCP

> AI 에이전트가 다른 앱(피그마, 버셀, 깃허브 등)을 직접 읽고 조작할 수 있게 해주는 연결 규칙.

## 설명
MCP는 Model Context Protocol의 줄임말이다. 앱 쪽이 "MCP 서버"를 열어 두면, AI는 그 서버가 제공하는 도구(읽기, 만들기, 내보내기 등)를 호출할 수 있다.
- 클로드 앱에서는 **커넥터**(Customize → Connectors)로 추가한다.
- 코덱스 앱에서는 **플러그인**으로 추가한다.
- 둘 다 연결 대상은 같은 MCP 서버다. 예: 피그마는 `https://mcp.figma.com/mcp`.

## 비유
AI에게 앱별 리모컨을 쥐여 주는 것. 리모컨에 있는 버튼(도구)만 누를 수 있다.

## 헷갈리기 쉬운 점
- MCP는 프로그램이 아니라 **연결 방식(규칙)**이다. 앱마다 MCP 서버가 따로 있다.
- 연결했다고 AI가 다 할 수 있는 건 아니다. 그 서버가 제공하는 도구 범위 안에서만 된다.
- 키·비밀번호를 채팅에 붙여 넣는 게 아니라, 로그인 승인(OAuth)으로 권한을 준다.

## 웹 개발에서는
- 피그마 MCP: 디자인 읽기(`get_design_context`, `get_screenshot`), 원본 이미지 꺼내기(`download_assets`), HTML을 피그마 레이어로 만들기(`html_to_figma`).
- 버셀 MCP: 배포 상태·로그·도메인 확인.
- 포트폴리오에서는 피그마에 정리한 작업을 에이전트가 읽어 R2 업로드·깃 커밋까지 이어서 한다.
