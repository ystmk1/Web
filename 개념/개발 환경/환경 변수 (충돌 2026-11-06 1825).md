# 환경 변수

> 코드 바깥에서 프로그램에 건네주는 설정값. 코드에 직접 쓰면 안 되거나, 환경마다 달라지는 값을 담는다.

## 설명
- 운영체제가 프로그램을 실행할 때 "이 값들 참고해" 하고 같이 넘겨주는 이름=값 목록이다. [[PATH]]도 환경 변수의 하나.
- 웹 개발에서는 보통 프로젝트 폴더의 `.env` 파일에 적는다.
  ```
  OPENAI_API_KEY=sk-...
  DATABASE_URL=...
  ```
- 코드에서는 이름으로 불러 쓴다. 코드는 공개돼도 실제 값은 내 컴퓨터(또는 서버 설정)에만 남는다.

## 비유
요리사에게 레시피(코드)와 따로 건네는 쪽지. "오늘 쓸 금고 비밀번호는 이거야." 레시피는 공개해도 쪽지는 공개하지 않는다.

## 헷갈리기 쉬운 점
- `.env` 파일을 [[깃허브|GitHub]]에 올리면 키가 공개된다. 그래서 `.gitignore`에 넣어 [[Git]]이 무시하게 한다.
- 프론트엔드 코드에 넣은 값은 방문자 브라우저로 그대로 전송되기 때문에 누구나 볼 수 있다. 그래서 비밀 값은 서버 쪽 환경 변수에만 둔다 → [[리버스 엔지니어링]]
- 내 컴퓨터의 `.env`는 배포한 서버로 자동으로 따라가지 않는다. [[버셀|Vercel]] 같은 곳의 설정 화면에 따로 넣어야 한다. "로컬에선 되는데 배포하면 안 돼요"의 단골 원인.
- 반대로, **배포된 사이트가 실제로 쓰지 않는 키는 Vercel에 넣을 필요가 없다.** 예를 들어 [[Cloudflare R2]] 업로드를 내 컴퓨터에서만 한다면 R2 키는 로컬 `.env`에만 두면 된다. 서버에 비밀 값을 덜 둘수록 안전하다.
- 키는 보통 짝으로 쓴다. Access Key ID만 있고 Secret Access Key가 없으면 아무것도 못 한다.
- Next.js에서 `NEXT_PUBLIC_`으로 시작하는 변수는 브라우저로 전송된다. 공개해도 되는 값(공개 이미지 주소 등)에만 붙이고, 비밀 키에는 절대 붙이지 않는다.

## 웹 개발에서는
- AI 서비스, 데이터베이스 같은 외부 [[API]] 키는 무조건 환경 변수로 넣는다.
- 바이브코딩 중 AI가 "`.env`에 키를 넣으세요"라고 하면 이 이야기다.
