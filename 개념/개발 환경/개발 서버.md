# 개발 서버

> 만들고 있는 사이트를 내 컴퓨터에서 바로 띄워 보여 주는 개발용 [[서버]]. 코드를 저장하면 브라우저 화면이 곧바로 바뀐다.

## 설명
- 보통 `npm run dev`로 켠다. 켜면 [[터미널]]에 `http://localhost:3000` 같은 주소가 나온다 → [[localhost]], [[포트]]
- 켜져 있는 동안 [[Node.js]] [[프로세스]]로 계속 살아 있으면서 세 가지 일을 한다.

| 하는 일 | 설명 |
|---|---|
| 요청에 응답 | 브라우저가 페이지를 달라고 하면 만들어서 보내 준다 → [[요청과 응답]] |
| 그때그때 번역 | 요청이 온 페이지만 브라우저가 아는 [[JavaScript]]로 바꾼다 → [[컴파일러]] |
| 파일 지켜보기 | 파일을 저장하면 바뀐 부분만 브라우저에 다시 보내 준다 (Fast Refresh, HMR) |

- 에러가 나면 터미널과 브라우저 화면에 자세한 에러 내용을 띄운다.
- 실제 서비스용 서버와 달리 속도 최적화를 하지 않는다. 대신 고친 결과를 빨리 보여 주는 데 집중한다.

## 비유
요리 프로그램의 시식 코너. 요리사가 간을 바꿀 때마다 바로 한 숟갈 떠서 맛보게 해 준다. 손님에게 파는 포장 도시락([[빌드]] 결과물)과는 다르다.

## 헷갈리기 쉬운 점
- **개발 서버는 내 컴퓨터에서만 돈다.** 터미널을 닫거나 Ctrl+C를 누르면 꺼지고, `localhost` 주소도 열리지 않는다. 남에게 보여 주려면 배포해야 한다 → [[버셀]]
- 개발 서버에서 잘 되어도 [[빌드]]에서 에러가 날 수 있다. 개발 서버는 요청 온 페이지만 번역하기 때문에, 열어 보지 않은 페이지의 문제는 빌드할 때 처음 드러난다.
- 터미널이 멈춘 것처럼 보여도 고장이 아니다. 서버가 요청을 기다리는 중이다. 다른 명령은 새 터미널 창에서 친다.
- 개발 서버를 두 개 켜면 [[포트]]가 겹친다. 두 번째 서버는 3001번처럼 다른 번호로 뜨거나 에러가 난다.

## 웹 개발에서는
- 바이브코딩의 기본 루프: 개발 서버를 켜 둔다 → AI가 코드를 고친다 → 저장되면 브라우저가 바로 바뀐다 → 눈으로 확인한다.
- 도구마다 기본 포트가 다르다. Next.js는 3000, Vite는 5173.
- `.env.local` 같은 [[환경 변수]] 파일은 개발 서버를 켤 때 읽는다. 값을 바꾸면 개발 서버를 껐다 다시 켠다.

## 관련 개념
- [[localhost]]: 개발 서버가 열리는 내 컴퓨터 주소
- [[포트]]: 개발 서버가 쓰는 번호 (3000 등)
- [[Node.js]]: 개발 서버를 실행하는 프로그램
- [[빌드]]: 배포용 결과물을 만드는 다른 과정
- [[프로세스]]: 켜져 있는 동안의 개발 서버
- [[서버]]: 개발 서버도 서버 역할을 한다
