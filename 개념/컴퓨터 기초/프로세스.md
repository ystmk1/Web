# 프로세스

> 실행 중인 프로그램. 메모리에 올라와 CPU를 쓰며 돌아가고 있는 상태.

## 설명
- 같은 [[프로그램]]을 여러 번 실행하면 프로세스도 여러 개가 된다.
- [[운영체제]]가 [[CPU]] 시간을 아주 잘게 나눠 여러 프로세스에 번갈아 주기 때문에, 동시에 돌아가는 것처럼 보인다. 코어가 여러 개면 실제로 동시에 돌기도 한다.
- 프로세스끼리는 [[메모리]]를 따로 쓴다. 그래서 한 프로그램이 멈춰도 다른 프로그램은 멀쩡하다.
- Windows 작업 관리자(Ctrl+Shift+Esc), macOS 활성 상태 보기에서 확인하고 강제로 끌 수 있다.
- 크롬은 탭·기능별로 프로세스를 여러 개 띄우기 때문에, 탭 하나가 멈춰도 [[브라우저]] 전체가 죽지 않는다.

## 비유
레시피(프로그램)를 보고 실제로 요리하는 중인 상태. 같은 레시피로 냄비 세 개를 동시에 끓이면 프로세스 세 개.

## 헷갈리기 쉬운 점
- 창을 닫았다고 프로세스가 꼭 끝나는 건 아니다. 뒤에서(백그라운드) 계속 도는 프로그램도 있다.
- 스레드: 프로세스 안에서 일을 나눠 하는 더 작은 단위. 지금은 이름만 알아도 충분하다.

## 웹 개발에서는
- `npm run dev`를 치면 개발 서버 프로세스가 시작돼 계속 살아 있다. 터미널이 다음 명령을 안 받고 멈춘 것처럼 보이는데, 고장이 아니라 일하는 중이다.
- 터미널에서 Ctrl+C = 그 프로세스를 끈다. 그러면 localhost 주소로 접속이 안 된다.
- 터미널 창을 닫으면 그 안에서 돌던 서버 프로세스도 보통 같이 꺼진다.
- 이미 켜둔 서버가 있는데 또 켜면, [[포트]](예: 3000)가 사용 중이라 3001처럼 다른 포트로 뜨거나 에러가 난다. 예전 프로세스를 끄면 해결된다.
