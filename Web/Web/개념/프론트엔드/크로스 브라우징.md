# 크로스 브라우징

> 서로 다른 OS·브라우저·기기에서도 웹이 최대한 같게, 적어도 깨지지 않게 보이도록 만드는 일.

## 설명
같은 웹이 다르게 보이는 원인과 대응.

| 원인 | 무슨 일이 생기나 | 대응 |
|---|---|---|
| [[렌더링 엔진]] 차이 | 특정 CSS가 Safari에서만 안 먹음 | 지원 여부 확인, 실제 기기로 테스트 |
| 폰트 | 방문자 컴퓨터에 없는 폰트는 다른 폰트로 대체 → 글자 폭·줄바꿈이 달라짐 | 웹폰트(예: Pretendard)를 같이 보내기 |
| 기본 부품 모양 | 버튼·체크박스·드롭다운·날짜 선택기가 OS 기본 모양으로 나옴 | 직접 스타일 지정 |
| 스크롤바 | Mac은 화면 위에 떠서 자리 차지 안 함, Windows는 옆에 자리를 차지 → 콘텐츠 폭이 달라짐 | 폭 계산에 여유 두기 |
| 화면 배율·해상도 | Windows 125%·150% 배율, Mac 레티나 → 크기·선명도가 다르게 느껴짐 | 고해상도 이미지, 상대 단위 |
| 사용자 설정 | 다크 모드, 글자 크기, 확대, 확장 프로그램 | 설정이 바뀌어도 안 깨지게 |
| 브라우저 기본 스타일 | 여백·글자 크기 기본값이 브라우저마다 조금 다름 | CSS 리셋 (Tailwind 같은 도구는 이미 포함) |

## 비유
같은 원고를 여러 인쇄소에 맡기는 것. 종이·잉크·기계가 달라서 결과물이 미세하게 다르니, 어디서 찍어도 괜찮게 나오도록 원고를 만든다.

## 헷갈리기 쉬운 점
- 목표는 "완전히 똑같이"가 아니라 "어디서든 의도대로 쓸 수 있게". 픽셀 단위로 같게 맞추는 건 비용이 크다.
- 개발자 도구의 모바일 모드로 확인한 건 크롬 엔진 기준이다. 아이폰 Safari는 실제 기기로 확인해야 한다.

## 웹 개발에서는
- 폰트 차이가 디자이너가 가장 먼저 체감하는 부분이다. 피그마에서 쓴 폰트는 웹폰트로 꼭 지정해야 방문자 화면에서도 같다.
- 최소 확인 세트: Windows 크롬 + 아이폰 Safari.
