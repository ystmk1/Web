# YAML의 뜻과 쓰임새

## 질문
> YAML이 무엇이고, 왜 프로그래밍 언어가 아니라 데이터 형식이라고 하는지.

## 답

### 한 줄로
[[YAML]]은 설정이나 데이터를 사람이 읽기 쉽게 적어두는 **글 형식**이다. 판단이나 반복을 시키지 못하고 내용을 적어두기만 한다. 그래서 [[프로그래밍 언어]]로 치지 않는다.

이름은 "YAML Ain't Markup Language"의 줄임말이다. 파일 확장자는 `.yaml` 또는 `.yml`이다. 둘은 같은 형식이다.

### 생김새
같은 데이터를 JSON과 YAML로 적으면 아래와 같다.

```json
{
  "name": "web-workshop",
  "port": 3000,
  "tags": ["웹", "질문"]
}
```

```yaml
# 동아리 사이트 설정
name: web-workshop
port: 3000
tags:
  - 웹
  - 질문
```

YAML의 기본 규칙은 네 가지다.
- `이름: 값` 형태로 적는다. 콜론 뒤에는 한 칸을 띄운다.
- 목록은 줄 앞에 `-`를 붙인다.
- 안에 들어가는 내용은 **스페이스로 들여쓴다**. 들여쓰기로 구조를 나타낸다.
- `#` 뒤의 글은 주석이다. 주석은 프로그램이 읽지 않는 메모다.

| | JSON | YAML |
|---|---|---|
| 구조 표시 | 중괄호 `{}`, 대괄호 `[]` | 들여쓰기 |
| 주석 | 쓸 수 없다 | `#`로 쓸 수 있다 |
| 따옴표 | 글자에 꼭 필요하다 | 대부분 생략할 수 있다 |
| 주로 쓰는 곳 | 프로그램끼리 데이터 주고받기 | 사람이 직접 고치는 설정 파일 |
| 비유 | 칸이 정해진 주문서 양식 | 손으로 쓴 정리 메모 |

### 헷갈리기 쉬운 점
- **들여쓰기 한 칸이 뜻을 바꾼다.** 들여쓰기가 어긋나면 데이터 구조가 달라지거나 에러가 난다. 탭 문자는 들여쓰기에 쓸 수 없기 때문에 스페이스만 쓴다.
- **글자가 다른 값으로 읽힐 수 있다.** 일부 YAML 도구에서는 `yes`, `no`, `on`, `off`가 참과 거짓으로 읽힌다. `010`처럼 0으로 시작하는 숫자도 다르게 읽힐 수 있다. 글자 그대로 쓰고 싶으면 따옴표로 감싼다.
- **YAML 파일만으로는 아무 일도 일어나지 않는다.** 다른 프로그램이 YAML 파일을 읽고 그 내용대로 움직인다. 식당 비유로 보면 YAML은 주문서이고, 요리는 주방(프로그램)이 한다.

### 웹 개발에서는
- 이 노트 맨 위의 `---` 사이 부분(프론트매터)도 YAML이다. 옵시디언과 블로그 도구가 이 부분을 읽어서 태그와 날짜를 안다.
- GitHub Actions 같은 자동 [[배포]] 설정, Docker Compose 설정이 YAML로 되어 있다. 바이브코딩 중에 AI가 `.yml` 파일을 만들어도 당황하지 않아도 된다.
- API 키 같은 비밀 값은 YAML 설정 파일에 직접 적지 않는다. 설정 파일은 GitHub에 함께 올라가는 경우가 많기 때문이다. 비밀 값은 [[환경 변수]]에 둔다.
- 에러 메시지에 "indentation"이나 "mapping"이 보이면 들여쓰기부터 확인한다.
