# npm run dev가 하는 일

## 질문
> `npm run dev`가 정확히 무엇을 해 주는지.

## 답

### 한 줄로
[[npm]]이 프로젝트의 `package.json`에 적힌 `dev` 명령을 대신 실행해 주고, Next.js 프로젝트에서는 그 명령이 [[개발 서버]]를 켠다.

### 1단계: npm이 하는 일 (심부름꾼)
`npm run dev`는 "package.json의 scripts 중 `dev`를 실행해 줘"라는 뜻이다.

```json
"scripts": {
  "dev": "next dev",
  "build": "next build",
  "start": "next start"
}
```

- 실제로 실행되는 것은 오른쪽의 `next dev`다. `dev`라는 이름은 정해진 약속일 뿐이고, 무엇이 실행되는지는 프로젝트마다 다르다.
- `npm run`으로 실행하면 `node_modules/.bin` 폴더가 잠깐 [[PATH]]에 더해진다. 그래서 `next` 프로그램을 따로 설치하지 않아도 프로젝트 안의 것을 찾아서 실행한다.

### 2단계: next dev가 하는 일 (개발 서버)
1. [[Node.js]] [[프로세스]]로 서버를 켜고 [[포트]] 3000번에서 요청을 기다린다. 3000번이 쓰이고 있으면 3001번처럼 다음 번호를 쓴다.
2. 터미널에 `http://localhost:3000` 주소를 보여 준다 → [[localhost]]
3. 브라우저가 페이지를 요청하면, 그 페이지 코드만 그때 번역해서 보내 준다. 그래서 처음 여는 페이지는 조금 느리다.
4. 파일을 지켜보다가 저장하면 바뀐 부분만 브라우저에 다시 보낸다. 새로고침 없이 화면이 바뀐다 (Fast Refresh).
5. 에러가 나면 터미널과 브라우저 화면에 자세히 보여 준다.
6. `.env.local` 같은 [[환경 변수]] 파일을 읽는다.

### dev, build, start 비교
| 명령 | 하는 일 | 언제 |
|---|---|---|
| `npm run dev` | 개발 서버 켜기. 빠르게 반영, 최적화 안 함 | 만드는 동안 |
| `npm run build` | 배포용 결과물(`.next`) 만들기. 최적화함 → [[빌드]] | 배포 전 확인 |
| `npm run start` | 빌드한 결과물로 실제 서비스용 서버 켜기 | build 뒤에만. [[버셀]]은 이 과정을 대신 해 준다 |

### 헷갈리기 쉬운 점
- **`npm run dev`는 설치가 아니다.** 필요한 패키지는 먼저 `npm install`로 받아야 한다. 안 받았으면 "next: command not found" 같은 에러가 난다.
- **켜 둔 동안만 사이트가 보인다.** Ctrl+C나 터미널 닫기 = 서버 끄기. 터미널이 멈춘 것처럼 보이는 것은 정상이다.
- **내 컴퓨터에서만 보인다.** 친구에게 `localhost:3000`을 보내도 친구 컴퓨터의 localhost를 찾는다. 공개하려면 배포한다.
- **dev에서 되면 끝이 아니다.** 개발 서버는 연 페이지만 번역하기 때문에, 배포 전에 `npm run build`를 한 번 돌려 보면 숨은 에러를 미리 잡는다.
- `npm start`와 `npm test`는 `run` 없이 써도 되는 특별한 이름이다. `dev`는 `run`을 붙여야 한다.

### 웹 개발에서는
- 워크숍 실습은 "터미널 하나는 `npm run dev` 전용으로 켜 두고, 다른 터미널이나 AI 에이전트로 코드를 고친다"를 기본으로 한다.
- AI 에이전트가 개발 서버를 직접 켜기도 한다. 이미 켜 둔 서버가 있으면 포트가 겹칠 수 있으니 어느 쪽이 켰는지 확인한다.
