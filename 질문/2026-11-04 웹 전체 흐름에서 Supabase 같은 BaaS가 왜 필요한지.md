# 웹 전체 흐름에서 Supabase 같은 BaaS가 왜 필요한지

## 질문
> BaaS가 뭔지보다, Supabase가 무슨 역할을 해주기 때문에 프로젝트에 쓰면 좋은지를 웹 원리 전체 흐름 안에서 설명해줘.

## 답
전체 흐름을 하나로 엮으면 이렇다.

1. **웹은 요청하면 응답받는 구조다.** [[클라이언트]]가 [[서버]]에 요청하면, 서버가 [[HTML]]·[[CSS]]·[[JavaScript]]를 돌려주고 브라우저가 화면으로 그린다([[DOM]]).
2. **그 서버를 찾아가려면 주소 체계가 필요하다.** [[도메인]]을 [[DNS]]가 IP로 바꿔주고, 그 서버는 [[웹 호스팅]](예: [[버셀]])이 띄운 것이다.
3. **여기까지는 "화면 보여주기"만 한다 ([[프론트엔드]]).** 회원가입·로그인, 데이터가 사라지지 않고 남는 것, 권한 체크는 브라우저 혼자 못 한다. 새로고침하면 날아가고, 코드가 공개되어 있어 비밀번호도 못 지킨다.
4. **그래서 데이터를 영구히 저장·보호하는 서버 쪽 로직(백엔드)이 필요하다.** 원래는 로그인 기능, 암호화, [[데이터베이스]] 구축, 권한 체크 서버 코드를 전부 직접 짜야 한다.
5. **이걸 대신 다 만들어 빌려주는 게 [[BaaS]], 그 대표가 [[Supabase]]다.** Auth(로그인), 세팅된 [[데이터베이스]](PostgreSQL), 권한 규칙까지 코드 몇 줄로 설정한다.

정리: 프론트엔드(버셀로 배포)는 "보여주는 쪽", Supabase는 "원래 직접 만들어야 했던 백엔드 일을 대신 해주는 쪽"이다. 짧은 시간에 진짜 작동하는 프로젝트를 만들려면 백엔드를 처음부터 짜는 대신 Supabase를 붙이는 게 현실적이다.
