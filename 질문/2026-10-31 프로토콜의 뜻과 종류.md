# 프로토콜의 뜻과 종류

## 질문
> HTTP 설명에 나오는 프로토콜이 무엇인지.

## 답

### 한 줄로
프로토콜은 컴퓨터끼리 미리 정해 둔 **대화 규칙**이다. 무엇을 어떤 순서로, 어떤 형식으로 보낼지 정한다. 웹에서 쓰는 규칙이 [[HTTP]]다.

사람끼리도 규칙이 없으면 대화가 안 된다. 택배를 보낼 때 받는 사람 주소를 정해진 칸에 쓰기 때문에 택배 기사가 어느 집이든 배달할 수 있다. 컴퓨터도 같다. 서로 다른 회사가 만든 컴퓨터라도 같은 프로토콜을 쓰면 말이 통한다.

### 프로토콜은 여러 개다
[[인터넷]]에는 하는 일에 따라 다른 프로토콜이 있다.

| 프로토콜 | 하는 일 | 기본 [[포트]] |
|---|---|---|
| HTTP / HTTPS | 웹 페이지와 데이터를 주고받는다 | 80 / 443 |
| [[DNS]] | [[도메인]]을 [[IP 주소]]로 바꿔 준다 | 53 |
| SMTP | 이메일을 보낸다 | 25, 587 등 |
| FTP | 파일을 전송한다 | 21 |
| SSH | 다른 컴퓨터에 원격으로 접속한다 | 22 |

### 프로토콜은 층을 쌓아서 쓴다
웹 페이지 하나를 받을 때도 프로토콜 여러 개가 함께 일한다. 택배에 비유하면 이렇다.

```
HTTP : 상자 안에 넣을 편지를 쓰는 형식 (무엇을 달라고 할지)
TCP  : 상자가 빠짐없이, 순서대로 도착하게 하는 규칙
IP   : 상자에 주소를 붙여서 목적지까지 보내는 규칙
```

HTTP는 맨 위층에서 내용만 신경 쓴다. 아래층의 TCP와 IP가 배달을 맡기 때문에 웹 개발자는 보통 HTTP만 알면 된다.

### 헷갈리기 쉬운 점
- **프로토콜은 프로그램이 아니다.** 프로토콜은 규칙이고, 그 규칙을 지키는 것은 [[브라우저]]와 [[서버]] 같은 [[프로그램]]이다. 비유하면 프로토콜은 교통 법규이고, 프로그램은 법규를 지키며 달리는 차다.
- **주소 맨 앞이 프로토콜 이름이다.** [[URL]]의 `https://`는 "HTTPS 규칙으로 대화하겠다"는 뜻이다. `ftp://`, `mailto:`처럼 다른 이름이 올 수도 있다.
- **포트와 프로토콜은 다르다.** 포트는 컴퓨터 안의 문 번호이고, 프로토콜은 그 문으로 오가는 대화 규칙이다. 80번, 443번은 관례로 정한 기본값이다. 그래서 `http://localhost:3000`처럼 다른 번호에서 HTTP를 써도 된다.
- **HTTPS는 완전히 새 규칙이 아니다.** HTTPS는 HTTP 대화를 암호화된 통로(TLS) 안에서 하는 것이다. 대화 형식은 HTTP와 같다.

### 웹 개발에서는
- 코드에서 `fetch()`로 데이터를 불러오면 브라우저가 HTTP [[요청과 응답|요청]]을 보낸다. 요청에 쓰는 [[HTTP 메소드]]와 응답에 붙는 [[HTTP 상태 코드]]는 모두 HTTP 규칙의 일부다.
- 채팅처럼 서버가 먼저 메시지를 보내야 하는 기능에는 WebSocket이라는 다른 프로토콜을 쓰기도 한다. 주소는 `ws://` 또는 `wss://`로 시작한다.
- HTTPS 페이지 안에서 `http://` 주소의 이미지나 스크립트를 불러오면 브라우저가 막거나 경고를 띄울 수 있다. 이것을 혼합 콘텐츠(mixed content)라고 한다. 배포한 뒤 이미지가 안 보이면 주소의 프로토콜을 확인한다.
