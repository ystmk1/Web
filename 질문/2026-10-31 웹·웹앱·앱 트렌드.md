# 웹·웹앱·앱 트렌드

## 질문
> 웹이냐 웹앱이냐 앱이냐, 기술적·동향적으로 지금 뭐가 트렌드인지.

## 답

### 한 줄로
"웹이냐 앱이냐"를 고르는 싸움은 약해지고 있다. 지금 흐름은 웹 기술(HTML·CSS·JS, React)로 만들어서 여러 자리(브라우저, 홈 화면, 앱 스토어, 다른 앱 안, AI 채팅 안)에 내보내는 것이다.

### 흐름 1: 웹앱(PWA)의 벽이 낮아졌다
- iOS가 막던 부분이 하나씩 풀렸다. iOS 16.4부터 홈 화면 웹앱에 푸시 알림이 된다.
- iOS 26부터 Safari에서 홈 화면에 추가한 사이트는 기본으로 웹앱으로 열린다. 사이트가 따로 설정하지 않아도 그렇다.
- 그래서 "설치 없이 앱처럼"이 예전보다 훨씬 쉬워졌다.

### 흐름 2: 그래도 앱은 안 사라진다
- 블루투스·NFC·백그라운드 위치·고성능 게임은 여전히 앱이 강하다.
- 스토어 노출과 재방문(푸시, 로그인 유지)도 앱이 유리하다.
- 그래서 많은 회사가 섞어 쓴다. 웹(검색으로 찾아옴)으로 사람을 데려오고, 앱으로 붙잡는다.

### 흐름 3: 앱도 웹 기술로 만든다
- iOS·Android를 따로 만들면 비용이 두 배라서, 코드 하나로 둘 다 만드는 크로스 플랫폼이 기본이 됐다.
- React Native: React를 알면 넘어가기 쉽다. 지금은 Expo로 시작하는 것이 공식 권장이다.
- Flutter: 구글이 만들고 Dart 언어를 쓴다. 점유율 조사에서 Flutter와 React Native가 1·2위를 다툰다 (숫자는 조사마다 다름).

### 흐름 4: 앱 안의 웹 (미니앱)
- 큰 앱 안에서 설치 없이 도는 작은 서비스다. 한국에서는 토스의 "앱인토스"가 대표적이다.
- 미니앱은 WebView(Vite + React) 또는 React Native로 만든다. 결국 웹 기술이다.

### 흐름 5: AI 채팅 안의 웹 (MCP Apps)
- 2026년 1월에 MCP Apps가 MCP의 첫 공식 확장으로 나왔다.
- 차트·폼 같은 화면을 Claude·ChatGPT 대화창 안에 띄운다. 속은 HTML·JS다.
- "내 서비스를 어디에 띄우나"의 새 자리가 생긴 것이다.

### 정리: 공통점
| 내보내는 곳 | 속은 |
|---|---|
| 브라우저 (웹) | HTML·CSS·JS |
| 홈 화면 (PWA) | HTML·CSS·JS + manifest |
| 앱 스토어 (React Native·Expo) | React |
| 다른 앱 안 (미니앱) | WebView 또는 React Native |
| AI 채팅 안 (MCP Apps) | HTML·JS |

다섯 군데 모두 웹 기술이 바탕이다. 그래서 웹을 먼저 배우면 가장 많이 써먹을 수 있다.

### 바이브코딩 입장에서
1. 처음에는 웹(HTML 또는 Next.js)으로 만든다.
2. 폰에서 앱처럼 쓰고 싶으면 PWA를 더한다.
3. 스토어 출시나 기기 기능이 꼭 필요하면 그때 Expo(React Native)로 간다.
