# R2 키를 Vercel 환경 변수에 넣어야 하는 경우

## 질문
> 상황별로 Vercel에 넣을 것(공개 주소만 / 없음 / 키 4개 / 바인딩) 표를 좀 더 자세히 설명해줘

## 답
R2에 닿는 길은 두 가지라서 넣을 값이 갈린다.

| 길 | 누가 | 필요한 것 |
|---|---|---|
| 공개 주소로 **보기** | 누구나 (방문자 브라우저) | 키 없음. 주소만 알면 됨 |
| API로 **올리기·지우기·목록** | 키를 가진 쪽만 | Access Key + Secret |

Vercel 환경 변수에 키를 넣는다 = **배포된 사이트 서버가 R2를 고칠 권한을 갖는다**는 뜻이다. 사이트가 고칠 일이 없으면 넣을 이유가 없고, 키는 적은 곳에 있을수록 안전하다.

### 1. 사이트는 공개 주소로 보여 주기만 함 → 키 없음
- 방문자 브라우저가 `<img src="https://media.내도메인/a.webp">`로 R2에서 직접 받아 온다. Vercel 서버는 R2에 로그인하지 않는다.
- `NEXT_PUBLIC_R2_URL`은 코드에서 "주소 앞부분 + 파일 이름"을 조합할 때만 필요하다. 콘텐츠 JSON에 전체 주소가 이미 들어 있으면 이것도 필요 없다.
- 이름이 `NEXT_PUBLIC_`으로 시작하는 값은 빌드할 때 브라우저 코드에 그대로 들어가서 누구나 볼 수 있다. 그래서 공개 주소처럼 원래 공개된 값만 이렇게 쓴다.

### 2. 업로드는 내 컴퓨터(로컬 스튜디오·스크립트)에서만 → Vercel엔 없음
- 스튜디오와 `npm run upload`는 내 컴퓨터에서 돌아서 내 컴퓨터의 `.env.local`만 읽는다. Vercel은 이 코드를 실행하지 않는다.
- 그래서 키는 `.env.local`에만 둔다. 사이트가 뚫려도 R2를 고칠 열쇠가 거기 없다.

### 3. 배포된 사이트가 직접 업로드·삭제·목록 조회 → 키 4개
- 예: 사이트 안의 관리자 업로드 페이지, 방문자가 사진을 올리는 기능. 이 코드는 Vercel 서버(API 라우트)에서 돌기 때문에 Vercel에 키가 있어야 한다.
- 각 값의 역할

| 이름 | 역할 | 비유 |
|---|---|---|
| `R2_ACCOUNT_ID` | 어느 Cloudflare 계정인지 (접속 주소를 만들 때 씀) | 건물 주소 |
| `R2_ACCESS_KEY_ID` | 키의 이름 | 아이디 |
| `R2_SECRET_ACCESS_KEY` | 키의 비밀값 | 비밀번호 |
| `R2_BUCKET` | 어느 버킷인지 | 창고 번호 |

- 지킬 것
    - 이 네 개에는 절대 `NEXT_PUBLIC_`을 붙이지 않는다. 붙이면 브라우저로 키가 새어 나간다.
    - 토큰 권한은 그 버킷 하나, 필요한 권한만 준다.
    - 업로드·삭제 API에는 로그인·관리자 확인을 꼭 넣는다. 없으면 누구나 올리고 지울 수 있다.
    - 파일 크기와 종류를 제한한다.

### 4. Cloudflare Worker에서 R2 사용 → 키 없음, 바인딩
- Worker는 Cloudflare 안에서 돌기 때문에 설정 파일(`wrangler.toml`)에 "이 버킷을 `env.MEDIA`로 연결"이라고 적으면([[바인딩]]) 키 없이 바로 쓴다.
- 키가 코드에도 환경 변수에도 없어서 가장 안전하다. 포트폴리오 댓글 Worker가 D1을 이 방식으로 쓴다.

### 배우는 입장에서 보면
"이 키를 어디에 넣지?"보다 **"그 코드가 어디서 실행되지?"**를 먼저 묻는다. 내 컴퓨터에서 돌면 `.env.local`, Vercel 서버에서 돌면 Vercel 환경 변수, 브라우저에서 돌면 비밀은 아예 못 넣는다(`NEXT_PUBLIC_`), Cloudflare 안에서 돌면 바인딩.
