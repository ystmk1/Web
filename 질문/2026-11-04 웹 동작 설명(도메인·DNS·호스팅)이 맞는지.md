# 웹 동작 설명(도메인·DNS·호스팅)이 맞는지

## 질문
> 웹은 서버에 원본이 있고 HTTP 메소드로 요청해서 HTML·CSS·JS를 받아온다. 접속하려면 도메인=DNS라우팅이 필요하고, 그 서버는 버셀 같은 호스팅 서비스다. 전문가들은 버셀 말고 어떻게 쓰는지?

## 답
전체 흐름은 맞지만 두 군데를 바로잡아야 한다.

### "도메인=DNS라우팅"은 틀렸다
- [[도메인]]: 사람이 읽는 주소 이름 (`google.com`)
- [[DNS]]: 그 이름을 실제 서버의 IP 주소로 바꿔주는 조회 시스템

"라우팅"은 보통 다른 맥락(예: [[라우트]] — URL 경로와 페이지를 잇는 것)에서 쓰여서 섞으면 헷갈린다. DNS가 하는 일은 정확히는 **이름→주소 변환(조회)**이다.

### "계속 받아온다"도 다듬을 부분
브라우저는 같은 CSS·JS 파일을 매번 새로 받지 않고 캐싱한다. 처음 접속할 때만 HTML·CSS·JS를 통째로 받고, 이후엔 필요한 데이터만 `fetch`로 부분적으로 받아오는 경우가 많다.

### 전문가는 버셀 대신 어떻게 쓰는지
규모가 커질수록 [[버셀]] 같은 "알아서 다 해주는" 서비스 대신 [[AWS]]처럼 부품을 직접 조합하는 쪽으로 간다.
- 서버를 직접 빌려(EC2 등) 띄우거나, 여러 서버에 트래픽을 나눠주는 로드밸런서를 둔다.
- 자체 데이터센터를 쓰는 큰 회사도 있다.
- DNS도 Route 53 같은 전문 서비스로 세밀하게 관리한다.
- 전 세계 어디서든 빠르게 받도록 [[CDN]]도 같이 쓴다.

버셀은 이 모든 걸 자동으로 대신 해주는 편한 버전이고, 전문가·대기업은 속을 직접 구성하는 경우가 많다.
