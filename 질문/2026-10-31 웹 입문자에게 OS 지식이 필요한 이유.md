# 웹 입문자에게 OS 지식이 필요한 이유

## 질문
> 웹 개발을 처음 배우는 사람에게 하드웨어·OS·프로그램 이야기가 필요할까?

## 답

### 결론: 필요하다, 단 아주 얇게
컴퓨터 구조를 공부하자는 게 아니라, **실제로 부딪히는 문제를 이해할 만큼만** 알면 된다.

이유는 하나다. **바이브코딩에서 막히는 지점의 상당수가 코드가 아니라 OS 층에서 생기기 때문**이다. 코드는 AI가 써주지만, 설치·실행·경로·권한 문제는 내 컴퓨터 환경에서 일어나서 AI도 내 화면을 보기 전까진 정확히 모른다.

### 딱 이 그림 하나만 기억하기
```
내가 만든 웹사이트 코드
 ↓ 실행해주는 프로그램 (Node.js, 브라우저)
 ↓
OS (Windows, macOS, Linux)  ← 설치·경로·권한·포트 문제는 대부분 여기
 ↓
하드웨어 (CPU, RAM, SSD)    ← 느려지면 여기
```

에러가 나면 **"이게 내 코드 문제야, 내 컴퓨터 환경(OS) 문제야?"** 를 먼저 구분할 수 있으면 된다. 그것만으로 AI에게 훨씬 정확하게 물어볼 수 있다.

### 실제로 부딪히는 상황
| 이런 일이 생기면                               | 어느 층 문제 | 알면 좋은 개념                                                      |
| --------------------------------------- | ------- | ------------------------------------------------------------- |
| 설치 방법이 Windows와 Mac이 다름                 | OS      | OS마다 파일 구조, [[터미널]], 설치 방식이 다름 → [[운영체제]]                     |
| "명령어를 찾을 수 없습니다"                        | OS      | [[PATH]]                                                      |
| "스크립트를 실행할 수 없습니다", `EACCES`            | OS      | 권한 → [[운영체제]]                                                 |
| 터미널을 닫았더니 사이트가 꺼짐                       | 프로그램    | [[프로세스]]                                                      |
| `localhost:3000`, "port already in use" | OS      | [[포트]]                                                        |
| `.env`에 키를 넣으라고 함                       | OS·프로그램 | [[환경 변수]]                                                     |
| 내 컴퓨터에선 되는데 배포하면 안 됨                    | OS      | 서버는 대부분 [[리눅스\|Linux]] → [[2026-10-17 로컬에선 되는데 배포하면 안 되는 이유]] |
| 개발 서버 여러 개 켜면 컴퓨터가 버벅임                  | 하드웨어    | [[메모리]] (RAM)                                                 |

### 짧게 하나씩
- **PATH = OS가 프로그램을 찾는 주소록.** 설치 후 "명령어를 찾을 수 없습니다"가 뜨면 터미널을 새로 열면 해결되는 경우가 많다.
- **권한 = OS가 지키는 출입 통제.** Windows의 스크립트 실행 차단, Mac의 `EACCES: permission denied`. 설치가 잘못된 게 아니라 OS가 문을 잠가둔 것일 때가 많다.
- **프로세스 = 켜져 있어야 동작.** `npm run dev`로 시작된 개발 서버 프로세스가 살아 있는 동안만 `localhost`에서 사이트가 보인다. 터미널을 닫거나 Ctrl+C를 누르면 꺼진다. 고장이 아니다.
- **포트 = 프로그램마다 받는 번호표.** "port 3000 already in use"는 이미 다른 프로세스가 3000번을 쓰고 있다는 뜻.
- **환경 변수 = 프로그램에 몰래 건네는 설정값.** [[API]] 키처럼 코드에 직접 쓰면 안 되는 값을 `.env`에 적어 건넨다.
- **서버는 대부분 Linux.** 파일 이름 대소문자를 구분해서 `Logo.png`/`logo.png` 문제가 생긴다.
- **RAM이 꽉 차면 느려진다.** 개발 서버, 브라우저 탭, 피그마, AI 도구를 동시에 켜면 코드 문제가 아니라 하드웨어 여유 문제.

### 몰라도 되는 것
- CPU가 명령을 처리하는 세부 원리, 메모리 주소 같은 구조
- OS 내부(커널)가 어떻게 만들어졌는지
- 컴파일러가 어떻게 번역하는지

이건 웹을 만드는 데 거의 영향이 없다.

### 워크숍에서 설명한다면 (5분)
1. 레스토랑 비유로 세 층을 한 장에 보여주기 (요리사=CPU, 조리대=RAM, 창고=SSD, 매니저=OS, 레시피=프로그램)
2. "에러가 나면 어느 층 문제인지 먼저 생각하자"는 메시지
3. 위 표에서 **PATH, 권한, 프로세스, 포트** 네 개만 짚기. 세팅 실습에서 거의 확실히 마주치는 것들이라, 미리 들으면 당일에 덜 당황한다.
