# 퍼블리셔·프론트엔드·백엔드가 나누는 일

## 질문
> 퍼블리셔는 마크업 개발자니까 HTML·CSS만 하고, JS는 백엔드가 맞는지.

## 답

### 한 줄로
퍼블리셔는 HTML·CSS로 화면을 옮기고, 프론트엔드 개발자는 거기에 JavaScript까지 더해 화면을 움직이게 만든다. 백엔드는 언어가 아니라 역할(서버 쪽 로직)을 가리키는 말이라서, 백엔드에 꼭 JavaScript를 쓰는 것도 아니다.

### 세 가지를 나란히 보면
| | 하는 일 | 쓰는 언어 |
|---|---|---|
| [[퍼블리셔]] | 디자인 시안을 화면으로 옮기기 | [[HTML]] · [[CSS]] (간단한 JS 조금) |
| 프론트엔드 개발자 | 화면을 만들고 움직이게 하기 | HTML · CSS · [[JavaScript]] |
| 백엔드 개발자 | 데이터 처리, 로그인, 저장 등 서버 쪽 로직 | 아무 언어나 가능 (Python, Java, PHP, Node.js 등) |

### 틀린 지점 두 개
- **"퍼블리셔 = HTML·CSS만"** → 대체로 맞다. 다만 회사마다 경계가 달라서, 퍼블리셔가 간단한 JS를 조금 맡기도 한다.
- **"JS는 백엔드"** → 틀렸다. [[JavaScript]]는 원래 **브라우저가 실행하는 프론트엔드 언어**로 태어났다. [[Node.js]]를 쓰면 JS를 서버에서도 돌릴 수 있지만, 이건 "JS로 백엔드도 짤 수 있다"는 선택지일 뿐이지 JS 자체가 백엔드 언어라는 뜻은 아니다.

### 헷갈리기 쉬운 점
- 백엔드는 특정 언어를 가리키는 말이 아니라 **위치(서버)와 역할(로직·데이터)**을 가리키는 말이다. 무엇으로 짰는지는 상관없다.
- 같은 JavaScript라도 브라우저에서 돌면 프론트엔드, Node.js로 서버에서 돌면 백엔드다. 언어가 아니라 **어디서 도는지**가 구분 기준이다.
- 프론트엔드 개발자는 "화면 담당"이라서 JS가 당연히 포함된다. 퍼블리셔는 그중 마크업·스타일만 떼어낸 더 좁은 역할이다.

### 웹 개발에서는
- 워크숍에서 React/Next.js로 화면을 만들 때 쓰는 JS는 전부 프론트엔드 영역이다. 같은 프로젝트 안에 서버 코드(API 라우트)가 있다면 그건 Node.js를 쓴 백엔드 부분이다 → [[백엔드·데이터]]
- "이 JS 코드가 브라우저에서 도는지, 서버에서 도는지"를 구분하는 습관이 프론트/백엔드 역할을 이해하는 데 도움이 된다.

## 관련 개념
- [[퍼블리셔]]: HTML·CSS 중심의 좁은 역할
- [[프론트엔드]]: HTML·CSS·JS를 모두 포함하는 더 넓은 역할
- [[JavaScript]]: 원래 프론트엔드 언어, Node.js로 백엔드에서도 씀
- [[백엔드·데이터]]: 언어가 아니라 역할로 구분되는 영역
