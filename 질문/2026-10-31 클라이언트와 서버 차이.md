# 클라이언트와 서버 차이

## 질문
> 클라이언트와 서버가 각각 무엇이고 어떻게 다른지.

## 답

### 한 줄로
요청하는 쪽이 [[클라이언트]], 응답하는 쪽이 [[서버]]다. 둘 다 기계 이름이 아니라 **역할** 이름이다.

| | 클라이언트 | 서버 |
|---|---|---|
| 하는 일 | 요청을 보낸다 | 요청을 기다렸다가 응답한다 |
| 어디서 도나 | 사용자 눈앞 (폰, 노트북) | 데이터센터의 컴퓨터 |
| 켜져 있는 시간 | 사용자가 쓸 때만 | 24시간 |
| 예 | 크롬, 카카오톡 앱, 인스타그램 앱 | 네이버 서버, 카카오 서버, [[버셀\|Vercel]] 서버 |
| 웹 개발 영역 | 프론트엔드 | 백엔드 |
| 비유 | 식당 손님 | 식당 주방 |

### 흐름
```
클라이언트 ──요청──▶ 서버
          ◀──응답──
```

항상 클라이언트가 먼저 요청한다. 서버는 요청이 와야 응답한다 → [[요청과 응답]]

### 헷갈리기 쉬운 점
- **한 컴퓨터가 둘 다 될 수 있다.** 내 노트북에서 `npm run dev`를 하면 개발 서버(서버)가 켜지고, 같은 노트북의 크롬(클라이언트)이 `localhost:3000`으로 요청한다.
- **서버도 클라이언트가 된다.** 웹 서버가 데이터베이스 서버나 AI 서비스에 요청할 때는, 그 순간 웹 서버가 클라이언트다.
- **서버는 특별한 기계가 아니다.** 서버 프로그램이 켜져 있는 평범한 컴퓨터다. 직접 두지 않고 빌려 쓰는 게 [[웹 호스팅]]이다.

### 웹 개발에서는
- 프론트엔드 코드는 클라이언트(방문자 브라우저)에서 돌아가기 때문에 누구나 볼 수 있다. 그래서 API 키 같은 비밀 값은 서버 쪽 [[환경 변수]]에 둔다.
- 에러가 났을 때 클라이언트 쪽 문제인지 서버 쪽 문제인지 구분하면 원인을 빨리 찾는다. 응답 코드 4xx는 요청 쪽, 5xx는 서버 쪽이다 → [[HTTP 상태 코드]]
