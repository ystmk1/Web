# 리버스 엔지니어링과 REA

## 질문
> 얼마 전 화제가 된 리버스 엔지니어링 도구는 "프로그래밍 언어 → 기계어" 단계와 연관 있는 거 아닌가? 암호화되어 있던 걸 프로그래밍 언어로 다시 복구하는 역설계를 AI로 하는 게 맞나?

## 답

### 반은 맞다
- **맞는 부분**: [[리버스 엔지니어링]]은 "프로그래밍 언어 → 기계어" 번역을 거꾸로 거슬러 올라가는 일이다. 그리고 REA는 이 일을 AI 에이전트가 하게 만든 도구다.
- **고칠 부분**: 실행 파일은 **암호화**된 게 아니라 **번역(컴파일)** 된 것이다. 번역하면서 변수 이름과 주석 같은 사람용 정보가 사라졌기 때문에 읽기 어려운 것이다. 그래서 "복구"도 원본 그대로가 아니라, 동작이 같은 비슷한 코드로 되살리는 것이다.

```
만들 때:     소스 코드 → 컴파일 → 기계어(실행 파일)
역설계할 때: 기계어 → 디스어셈블(어셈블리어) → 디컴파일(소스 코드 비슷한 것)
```

| | 무엇을 한 것인가 | 되돌릴 수 있나 |
|---|---|---|
| 컴파일 | 사람용 코드를 기계어로 번역 | 비슷하게는 되돌릴 수 있다 |
| 난독화 | 코드를 일부러 읽기 어렵게 섞음 | 시간이 들지만 풀 수 있다 |
| 암호화 | 열쇠(키)로 잠금 | 열쇠 없이는 사실상 못 푼다 |

### REA가 뭔가
- 이름은 **REA(Reverse Engineer Anything)**. GitHub의 `morluto/rea`에 있는 MIT 라이선스 [[오픈소스]] 도구다.
- [[MCP]] 서버와 CLI로 되어 있다. Claude Code, Codex, Cursor 같은 코딩 에이전트에 연결해서 쓴다.
- 2026년 4월에 공개됐고, 10월 초에 GitHub Trending 1위에 오르면서 화제가 됐다.
- 분석 대상: 실행 파일, Electron 앱, 안드로이드 앱(APK), 펌웨어, 웹사이트.

```
나: "이 앱 로그인은 어떻게 동작해?"
 ↓
AI 에이전트가 REA 도구를 호출
 ↓
REA가 Ghidra·IDA 같은 분석 도구를 대신 돌림
 ↓
결과(의사코드, 구조, 네트워크 기록)를 근거와 함께 AI에게 전달
 ↓
AI가 해석해서 답변
```

### 원래 있던 기술인데 화제가 된 이유
- Ghidra나 IDA 같은 분석 도구는 오래전부터 있었다. 새로운 건 **연결 방식**이다.
- 예전에는 어셈블리어를 읽고 도구를 다룰 줄 아는 전문가가 필요했다. 이제는 AI가 도구를 대신 돌리기 때문에, 사람은 "이 기능 어떻게 동작해?"라고 말로 물으면 된다.
- 디컴파일 결과는 `FUN_00401a20` 같은 의미 없는 이름투성이다. 이걸 읽고 이름을 붙이는 지루한 작업을 AI가 빠르게 한다.
- 결과마다 어느 파일의 어디서 나온 정보인지 근거를 같이 남긴다.

### 주의할 점
- 앱을 통째로 복제해주는 도구가 아니다. AI가 정리한 결과도 틀릴 수 있다.
- 분석할 권한이 있는 프로그램에만 써야 한다. 남의 프로그램을 베끼면 저작권·약관 문제가 생긴다.
- GitHub에 가짜 복제본이 돌았다. 공식 저장소(`morluto/rea`)와 npm 패키지(`rea-agents`)만 써야 한다.

### 웹 개발과 연결하면
웹사이트의 [[JavaScript]]는 기계어로 컴파일되지 않고 브라우저로 그대로 전송된다. 그래서 REA 같은 도구가 없어도 개발자 도구(F12)에서 누구나 코드를 볼 수 있다. 이런 이유로 프론트엔드 코드에는 API 키나 비밀번호를 넣으면 안 되고, 비밀 값은 서버 쪽 [[환경 변수]]에 둔다.
