# 컴퓨터가 일하는 방식

## 질문
> 컴퓨터는 어떻게 일하는지: 하드웨어, OS, 프로그램 (웹 개발 배우는 입장에서)

## 답

### 큰 그림: 3층 구조

```
나 (클릭, 타이핑)
 ↓
프로그램: 크롬, VS Code, 피그마, 카카오톡
 ↓  "파일 열어줘", "화면에 그려줘", "인터넷 연결해줘"
OS(운영체제): Windows, macOS, Linux
 ↓  드라이버를 통해 실제 기계에 명령
하드웨어: CPU, 메모리, 저장장치, 그래픽카드
```

| 층 | 하는 일 | 레스토랑 비유 |
|---|---|---|
| [[프로그램]] | 실제로 하고 싶은 일 (크롬, VS Code, 개발 서버) | 레시피 |
| [[운영체제]] (OS) | 하드웨어를 관리하고 프로그램들에게 나눠줌 | 매니저 |
| [[하드웨어]] | 실제로 계산하고 저장하는 부품 | 주방 설비와 요리사 |

위층은 아래층이 어떻게 동작하는지 몰라도 된다. 프로그램은 하드웨어를 직접 만지지 않고, 항상 OS에게 부탁한다.

### 1. 하드웨어: 실제로 일하는 기계
컴퓨터 안의 모든 정보는 결국 전기가 흐르냐(1) 안 흐르냐(0)의 조합으로 저장되고 계산된다.

| 부품 | 하는 일 | 비유 |
|---|---|---|
| [[CPU]] | 명령을 하나씩 읽고 계산. 1초에 수십억 번 | 요리사 |
| [[메모리]] (RAM) | 지금 쓰는 작업을 올려두는 곳. 빠르지만 꺼지면 사라짐 | 조리대 |
| [[저장장치]] (SSD) | 파일과 프로그램을 보관. 느리지만 꺼져도 남음 | 냉장고·창고 |
| GPU (그래픽카드) | 화면 그리기, 대량 병렬 계산 (3D, 영상, AI) |  |
| 입출력 장치 | 키보드·마우스·모니터·네트워크 | 주문 받는 창구 |

프로그램을 많이 켜면 느려지는 건 조리대(RAM)가 꽉 차서다.

### 2. 운영체제: 하드웨어를 관리하는 매니저
Windows, macOS, Linux. CPU 시간과 메모리를 프로그램들에 나눠주고, 파일을 폴더로 정리하고, 장치를 **드라이버**로 다루고, 권한을 관리한다. [[터미널]]은 OS에게 글자로 직접 명령하는 창이다.

### 3. 프로그램: 무엇을 할지 적어둔 명령서
- 사람은 [[JavaScript]], [[Python]] 같은 [[프로그래밍 언어]]로 코드를 쓰고, CPU는 0과 1로 된 기계어만 알아듣는다. 그래서 중간에 번역이 필요하다 → [[2026-10-31 프로그래밍 언어와 기계어 차이]]
- 프로그램은 저장장치에 가만히 있는 파일(레시피)이고, 실행되면 메모리에 올라와 CPU가 돌리는 [[프로세스]](지금 만들고 있는 요리)가 된다. 작업 관리자에 보이는 목록이 프로세스다.

### 흐름 예시 1: 크롬을 켜고 웹사이트를 열 때
```
1. 크롬 아이콘 더블클릭 → 마우스(하드웨어) 신호를 OS가 받음
2. OS가 SSD에서 크롬 프로그램 파일을 찾아 RAM에 올림 → 크롬이 프로세스가 됨
3. CPU가 크롬의 명령을 하나씩 실행
4. 주소창에 주소 입력 → 크롬이 OS에게 "인터넷 연결해줘"
   → OS가 네트워크 장치로 다른 컴퓨터(서버)에 요청
5. 서버가 HTML, CSS, JS를 보내줌
6. 크롬이 그걸 해석해서 OS에게 "화면에 이렇게 그려줘" → 드라이버 → GPU → 모니터
```

### 흐름 예시 2: 코드를 고치고 브라우저에서 보기까지
```
1. 키보드로 입력 → OS가 VS Code에 전달 → 고친 내용은 아직 메모리에만 있음
2. Ctrl+S → OS를 거쳐 저장장치에 파일로 저장
3. npm run dev → Node.js가 개발 서버 프로세스로 실행되고, 파일을 읽어 서버를 염
4. 브라우저(또 다른 프로세스)가 localhost:3000에 요청 → 받은 코드를 실행해서 화면을 그림
```

### 웹 개발에서 꼭 기억할 것
- [[브라우저]]도 프로그램이다. HTML·CSS·JS는 브라우저라는 프로그램 안에서 실행된다.
- [[서버]]도 특별한 기계가 아니라 같은 구조의 컴퓨터(보통 Linux)다. 내 노트북도 `npm run dev` 하면 서버 역할을 한다.
- Node.js는 원래 브라우저 안에서만 돌던 JavaScript를 내 컴퓨터(OS 위)에서 바로 실행하게 해주는 프로그램이다. 그래서 개발 환경 세팅 때 설치한다.
- 저장(Ctrl+S)을 안 하면 아직 메모리에만 있기 때문에 화면에 반영되지 않는다.
- `npm run dev` 후 터미널이 멈춘 것 같은 건 서버 프로세스가 일하는 중. Ctrl+C로 끈다.
- OS마다 파일 구조, 권한 방식, 터미널 명령어가 다르기 때문에 설치 명령도 OS마다 다르다.
